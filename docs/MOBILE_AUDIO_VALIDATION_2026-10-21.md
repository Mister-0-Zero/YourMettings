## Физическое испытание

- Получено **1826,5 секунды аудио (30:26,5)**. Одна аудиосессия, семь различных фрагментов, один transcript.
- Пауза остановила таймер и рост текущего файла; продолжение использовало тот же файл. Стрелка назад и повторное открытие экрана сохранили запись.
- Запись продолжалась в фоне, на Home, в системных настройках сведений о приложении и при выключенном/заблокированном экране. Были несколько длительных интервалов с `mWakefulness=Dozing`; пользователь также включал экран. Это **не** утверждение о 30 минутах непрерывно выключенного экрана.
- Android подтвердил `isForeground=true`, service type `0x80` (microphone), постоянное уведомление. После завершения служба микрофона остановилась.
- Отключение существующего `adb reverse` имитировало потерю USB-доступа к backend. Первый закрытый WAV (301,8 с) остался на телефоне, следующий файл продолжил расти. После восстановления соединения файл принят и распознан; локальный файл удалён после ACK. Физическое отключение USB-кабеля отдельно не выполнялось.
- GigaAM-worker был остановлен: новый фрагмент принят и оставался queued. После запуска существующего worker очередь обработана.
- Worker дополнительно аварийно остановлен во время ASR фрагмента №4. После запуска тот же фрагмент завершился с `attempt=2`, без второго chunk/transcript. Старые done-фрагменты сохранили attempt=1.
- FastAPI перезапущен с прежними аргументами: та же сессия и ранее принятые данные сохранились. PostgreSQL/Ollama и исходный код backend не изменялись.
- Пробная отправка некорректных байтов на ещё не занятый номер получила 422 invalid_audio; число принятых частей не изменилось. Затем настоящий WAV с этим номером принят штатно. Поведение локальной очереди при отказе проверено автоматическими тестами отдельно.
- Нормальная кнопка «Завершить запись» закрыла последний файл; все семь файлов приняты, complete подтверждён, ASR завершён. На телефоне больше нет локальных WAV этой сессии.
- Повторная установка/перезапуск приложения после ASR сохранили ID сессии и открыли полный транскрипт. **20 823 символа** в локальном черновике проверки точно совпали с ответом GET transcript; обрезки не было.

## Автоматические проверки

`flutter analyze --no-pub`: без замечаний. `flutter test --no-pub`: **121 тест прошёл**. Android debug APK собран.

Новые проверки включают:

- побайтовую непрерывность PCM при произвольных нечётных входных буферах;
- 11 минут PCM и реальные границы 5 + 5 + 1 минута: SHA256 склеенных сэмплов совпал с исходным потоком;
- восстановление WAV после аварии до публикации метаданных;
- отсутствие удаления до проверенного ACK; повтор идентичных байтов;
- восстановление офлайн-очереди новым экземпляром и идемпотентное создание с потерянным ответом;
- несколько пауз/продолжений при единственном старте микрофона;
- новый фрагмент во время незавершённой отправки: сначала все ACK, затем complete;
- управляемый сбой записи на диск: микрофон останавливается, сохранённый файл остаётся;
- явный PATCH → актуальный hash → audio confirm, потеря ответа confirm без нового запуска Qwen;
- гонку принятия результата с незавершённым polling: закрытая сессия не появляется снова;
- форму перед записью и безопасную навигацию в обеих темах;
- прежние проверки текстового ввода, папок, WYSIWYG, сохранения, ссылок и оформления.

## Оставшиеся физические проверки

- Полный путь **редактирование распознанного подкаста → явное подтверждение → реальный Qwen → summary → «Принять»** не выполнен на этой записи: транскрипт оставлен пользователю для проверки. Протокол подтверждения и потерянного ответа проверен автоматическим тестом.
- Принудительное убийство Android-процесса с открытым PCM-файлом проверено моделью сбоя/восстановления в тестах, но отдельное такое испытание на HONOR не выполнено после указания закончить.
- Точная сверка каждого слова и стыка с исходным подкастом не выполнена: исходный файл/его эталонный транскрипт не передавались. Пользовательская проверка ASR остаётся необходимой.
- Повторяющиеся паузы проверены автоматически; на физическом устройстве выполнена одна пауза/продолжение.
- Новый индикатор уровня входит в установленный финальный APK; длительная запись выполнялась предыдущей промежуточной сборкой без этого индикатора. На финальной версии микрофон заново не включался после просьбы закончить.
- macOS/Xcode/iPhone отсутствуют: сборка и физические проверки iOS не выполнены. Архитектура и чек-лист: `MOBILE_AUDIO_IMPLEMENTATION.md`.
