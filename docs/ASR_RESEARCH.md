omegaconf 2.3, numpy 2, onnx 1.19, onnxruntime 1.23, soundfile,
sentencepiece, tqdm; torch/torchaudio >=2.6. Выбран torch/torchaudio 2.10.0
с CUDA 12.6: эта версия соответствует ограничениям официального longform extra.
Отдельный CUDA Toolkit не устанавливается; используются библиотеки wheel.
[GigaAM pyproject](https://github.com/salute-developers/GigaAM/blob/7447938d791c4f3e643386ee22c33777004293a5/pyproject.toml),

скрипт копирует его в `asr/tools/ffmpeg.exe` и добавляет каталог только в PATH своего процесса.
Системный PATH не изменяется. Flash Attention отключён (`use_flash=False`),
сборка дополнительных CUDA-расширений не требуется.
Фактически установлен FFmpeg 7.1 essentials (gyan.dev), сборка с `--enable-gpl`
и `--enable-version3`; это нужно учитывать при будущем распространении бинарника.
Сейчас он используется локально и в Git не включён.

Обнаруженная проблема Windows: SentencePiece 0.2.2 не открывал токенизатор по
абсолютному пути с кириллицей (`C:\Users\Алексей\...`). CLI разрешает входной

рабочий каталог общий для процесса. Для worker нужен заранее заданный cwd.

## Установка и запуск (PowerShell)

Из корня ASR worktree, с Python 3.11 в PATH:

```powershell
.\asr\setup.ps1
.\asr\.venv\Scripts\python.exe .\asr\transcribe.py --input .\asr\audio\example.wav --output .\asr\results\example.txt --repeat 3
```

`requirements-lock.txt` фиксирует фактически установленный базовый набор зависимостей;
setup применяет его как constraints. Longform extra в этот lock не входит.
Проверка `pip check` завершилась без конфликтов. CUDA доступна, compute capability
RTX 3090 — 8.6. CUDA wheel скачан напрямую после медленной загрузки pip;
его SHA256 `4749cd32e32ed55179ff2ff0407e0ae5077fe4d332bfa49258f4578d09eccb40`
совпал с [официальным индексом](https://download.pytorch.org/whl/cu126/torch/).
Скрипт установки использует стандартный официальный PyTorch index.

Можно передать абсолютный путь к своему WAV, MP3, M4A, FLAC или другому файлу,
который декодирует установленная сборка FFmpeg. Поддержка конкретного кодека
проверяется реальным декодированием, а не расширением. Скрипт нормализует вход
во временный mono WAV PCM16 16 kHz. Длительность считается по числу отсчётов.
Временный WAV удаляется при обычном завершении, ошибке или Ctrl+C.
При аварийном завершении ОС/процесса очистка временного файла не гарантирована.

TXT сохраняется после успешного распознавания через замену временного файла.
Рядом создаётся `<output>.metrics.json`: длительность, время загрузки,
время/RTF каждого запуска, GPU, версии torch/CUDA, peak allocated/reserved VRAM.
RTF считается по времени вызова официального распознавания с CUDA synchronize;
загрузка модели и предварительное декодирование указаны отдельно. Для longform
в вызов входят VAD и внутреннее чтение/сегментация. `total_seconds_before_save`
включает импорты, предварительное декодирование, загрузку и все повторы.
Peak VRAM — счётчики allocator PyTorch за загрузку и все повторы; они не включают
всю память CUDA-контекста и чужих процессов. Это не общий пик `nvidia-smi`.
Для longform дополнительно сохраняются времена сегментов в `.segments.json`.
Первый запуск с отсутствующими весами включает скачивание во время загрузки;
для измерений следует предварительно скачать веса. Первый inference включает
прогрев; повторные запуски используют одну модель.

## Длинные записи: официальный механизм

`transcribe` ограничен 25 секундами. Для большего входа используется
`transcribe_longform`, без собственной системы нарезки.
Официальный `longform` extra требует pyannote.audio 4.0, torch/torchaudio 2.10,
torchcodec 0.10, numba >=0.62, pyarrow >=23, transformers 5.
Нужны принятие условий [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0)
и локально заданный `HF_TOKEN`. Токен не следует вставлять в чат или Git.
Пользователь принял условия; сохранённый в пользовательском окружении Windows
`HF_TOKEN` проверен запросом auth-check: HTTP 200. Значение токена не выводится.
CLI читает его из окружения процесса, а при отсутствии — из пользовательской
переменной Windows. Токен в файлы проекта и результаты не записывается.

Установка проверенного полного стека (после базовой установки):

```powershell
.\asr\setup-longform.ps1
.\asr\.venv\Scripts\python.exe .\asr\transcribe.py --input 'C:\Users\Алексей\Music\asr\opeka.mp3' --output .\asr\results\opeka-full.txt
```

Установлены pyannote.audio 4.0.7, TorchCodec 0.10.0 и остальные зависимости;
точные версии — `asr/requirements-longform-lock.txt`. `pip check` прошёл.
Первый longform-запуск завершился ошибкой декодирования: static FFmpeg 7.1 не
предоставляет DLL, необходимые TorchCodec. Установлена локальная shared-сборка
FFmpeg 8.1.2 из GitHub-зеркала gyan.dev, на которое ссылается официальный сайт FFmpeg.
SHA256 архива `cba748035c21ce1431d0823c7a3a711f38616f89f87a265dceddf9b7f6749d2d`
сверен с сайтом сборщика. DLL находятся в `asr/tools/ffmpeg-shared/bin`;
CLI добавляет этот каталог только в свой PATH и DLL search path.
Системная установка, права администратора, WSL2 и изменение системного PATH не нужны.
Сборка GPLv3; распространять бинарники нужно с соблюдением её лицензии.
[Требование TorchCodec к shared FFmpeg](https://raw.githubusercontent.com/pytorch/torchcodec/v0.10.0/README.md),
[официальные ссылки на Windows-сборки](https://ffmpeg.org/download.html),
[сборщик и контрольные суммы](https://www.gyan.dev/ffmpeg/builds/).

Модель VAD скачана в `asr/.cache/huggingface`, вне Git. Из-за отсутствия symlink
на Windows HF cache может занимать больше места; Developer Mode не включался.
CLI по умолчанию отключает телеметрию HF/pyannote переменными своего процесса.

По исходникам pinned версии:

- VAD находит речевые интервалы; они объединяются в фрагменты с целевой максимальной
  длительностью 22 с и минимальной 15 с. Непрерывные интервалы более 30 с принудительно делятся.
- Фрагменты распознаются независимо, состояние RNNT между ними не переносится.
  `LongformTranscriptionResult.text` соединяет тексты пробелом, без смыслового редактирования
  и удаления повторов; сегменты содержат времена начала/конца. Это не диаризация.
- Весь звук загружается в RAM; список сегментов создаётся до распознавания.
  Только PCM float32 mono 16 kHz занимает примерно 110 MiB за 30 минут
  и 330 MiB за 90 минут; это нижняя оценка, не замер общей RAM процесса.
- Upstream batch size по умолчанию 16; наш CLI начинает с 1, чтобы ограничить VRAM
  при соседстве с Qwen. Оптимальный batch требует измерений.
- Метод возвращает результат после обработки всех фрагментов; встроенного checkpoint,
  сохранения прогресса и продолжения после прерывания нет. При ошибке нужен повтор.
  Скрипт не сохраняет частичный текст как успешный результат.

## Рекомендация по последующей интеграции

Рекомендация, не реализованная интеграция: один локальный ASR worker/процесс
со своим Python-окружением и одной загруженной моделью; FastAPI создаёт job
и сообщает статус. Это сохраняет независимые зависимости ASR и backend,
не блокирует event loop и не размножает копии модели при нескольких API workers.
Загрузка модели прямо в FastAPI допустима для однопроцессного прототипа,
но усложняет обновление torch и контроль VRAM.

Начать с последовательной обработки и существующего состояния job в PostgreSQL.
Для 30–90-минутных записей нужна очередь/планирование и восстановление статусов
после перезапуска; Redis/Celery пока не требуются. Не держать транзакцию БД
открытой на время ASR. Ошибка должна давать читаемый статус и возможность повторить.

ASR и Ollama/Qwen конкурируют за VRAM. До измерения совместной нагрузки
не запускать несколько ASR одновременно; планировать ASR и LLM последовательно.
Не выгружать чужую модель и не менять настройки Ollama автоматически.
Потребность в управляемой выгрузке согласовать при интеграции. При OOM не скрывать
ошибку автоматическим CPU fallback; дать явную возможность повторить с `--device cpu`.
После успешной записи транскрипта в БД временное аудио удаляет backend;
исследовательский CLI исходный пользовательский файл не удаляет.
