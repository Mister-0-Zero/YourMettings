## Backend и авторизованный USB

Координатор передал явное «backend готов»: код `1854d87`, схема 0010, локальный API **http://127.0.0.1:8001/api/v1/**, ASR/Ollama готовы. Миграцию/backup/запуск зависимостей выполнял backend-агент, не мобильный агент. По сообщению координатора локальный demo-сеанс ограничен **1 ноября 2026, 01:17 МСК**. Публичный .env/истёкший внешний demo-доступ не продлевались. В этом этапе мобильный агент backend/VPS/БД/Firewall/VPN не настраивал.

Настроен `adb reverse tcp:8000 tcp:8001`; приложение использует штатный USB origin **http://127.0.0.1:8000** и base `/api/v1/`. API по USB тоже требует **X-Demo-Key**, включая health и auth/me. Штатное «Сохранить и применить» подтвердило demo-доступ. Переключение на USB — прямой выбор пользователя, а не обход авторизации.

В USB-origin не оказалось прежнего сохранённого ключа. Сначала был задан ручной вопрос; затем координатор подтвердил provision того же ключа из локальной backend-конфигурации в пустое скрытое поле. Перед вводом проверены профиль, obscured field и его пустота. Локальный helper использовал credential только в памяти, передал через STDIN `adb shell`, без значения в argv процессов Windows, stdout/stderr были отброшены. Выполнено обычное UI-сохранение в origin-specific SecureStorage. HTTPS vault не извлекался и не переписывался; HTTPS-адрес и остальные параметры сохранены. Ключ не выведен в чат/логи и не попал в screenshots/Git.

После полного перезапуска приложение само восстановило USB-профиль и доступ к папке. В конце оставлены USB и указанная переадресация, чтобы пользователь мог продолжить по кабелю. После окончания локального сеанса или отключения кабеля доступ зависит от наличия соответствующего сервера/reverse; внешний HTTPS этим тестом не восстановлен.
