## Запрос и действия пользователя

`PUT /api/v1/summaries/{id}/folders`, существующая авторизация, JSON:

```json
{
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"],
  "expected_folder_ids": ["26749d67-e0ca-47ae-b7c3-9974ff8c67ac"]
}
```

`folder_ids` — полный желаемый набор, 1–100 различных UUID. `expected_folder_ids` — последний прочитанный набор из GET SummaryOut, 0–100 различных UUID; отсутствие допустимо только ради старых клиентов. Явный null запрещён. Порядок не имеет значения.

При исходном A,C:

| Действие | folder_ids | expected_folder_ids |
|---|---|---|
| Добавить в B | A,B,C | A,C |
| Переместить из A в B | B,C | A,C |
| Переместить из A в A | A,C | A,C |

Не создавайте второй summary для размещения: документ, источник и версия содержания общие, редактирование видно из каждой папки. Перед перемещением сохраняйте остальные размещения, а не отправляйте только B.

## Ответы и восстановление

- 200: обычный SummaryOut. Если target уже текущий, это no-op даже со старым expected; updated_at и version не меняются. После реального изменения меняется только updated_at/размещения.
- 409 `summary_folders_conflict`: текущий набор отличается от expected и target. Сохранить намерение, прочитать GET, показать изменение пользователю и пересчитать действие после его решения. Не повторять старый target с новым expected автоматически.
- 404: summary или целевая папка отсутствует/недоступна. Не создавать замену скрытно.
- 422 `validation_error`: неверные UUID, null, дубликаты/лимиты; target [] запрещён.
- Остальные сетевые/авторизационные ошибки обрабатываются как у остальных операций текущего профиля; локальное намерение не терять.

При потерянном ответе повторить точный PUT с прежними target/expected. Уже достигнутый target вернёт 200; другое актуальное состояние даст 409. Это CAS текущего набора без durable receipt и без обнаружения истории A→B→A; нельзя обещать exactly-once операцию. Без expected остаётся старый last-write-wins.

Принятие варианта summary не восстанавливает старые папки. Удаление папки сохраняет документ в других размещениях; если документ удалён целиком, последующий PUT возвращает 404. Требования к папкам при создании/confirm не менялись.
