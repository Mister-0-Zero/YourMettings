# Проверка backend MVP

Дата: 2026-10-13. Ветка backend. mobile не изменён, merge в main не выполнен.

## Автоматические проверки

- pytest: 62 успешных теста на API, Ollama MockTransport и настоящем PostgreSQL 18. SQLite не использовался.
- PostgreSQL: миграция на чистую test-БД, downgrade/upgrade, уникальность user + transcript, внешние ключи, идемпотентная инициализация пользователя.
- Конкурентное создание с Idempotency-Key создаёт один transcript; повтор с другим текстом отклоняется.
- Генерация блокирует редактирование, параллельный повтор не вызывает модель второй раз, во время ожидания модели нет idle in transaction.
- Ошибка допускает редактирование до первого успеха; успех навсегда блокирует текст. Последний summary удаляет ненужный transcript; общие источники, активные обработки и внешние FK-ссылки сохраняются.
- Проверены чужие transcript, summary и folders, редактирование summary, несколько папок, замена связей, фильтр и пагинация.
- OpenAPI содержит согласованный набор endpoints, включая удаление папок с обязательным mode=with_contents и confirm=true.
- alembic check: расхождений моделей и миграций нет. pip check: конфликты отсутствуют.

## Реальный end-to-end

Через HTTP на loopback, dev PostgreSQL и установленную Ollama-модель `qwen3.8:27b`:

создание папки → запрос с detailed, шестью акцентами и дополнительными инструкциями → идемпотентный повтор → polling ready → получение Markdown без таблиц → изменение названия и содержания → список по папке → удаление папки с содержимым → проверка удаления summary и ненужного transcript.

Модель вернула решения, задачу Сергею в текстовом блоке с указанным сроком и открытый вопрос бюджета. Проверка отсутствия Markdown-таблиц прошла. Новые модели не скачивались.

## Практические ограничения

Владелец проекта подтвердил доступ с ПК и физического телефона к 192.168.1.100:8000 при отключённом VPN. Дополнительные изменения Firewall не требуются. VPN в рамках доработки не исследуется.

Один серверный процесс; фоновые задачи не являются устойчивой очередью. После перезапуска доступен явный повтор. Длинные тексты и нагрузка GPU отдельно не проверены; контекст модели может быть меньше символьного лимита API. Нет авторизации, ASR, sharing и автоматического разбиения длинных текстов. Удаление папок во время генерации временно отклоняется (409), чтобы сохранить принятые параметры обработки.

Обновлённый E2E-скрипт удаляет созданные этим запуском folders, summaries и transcripts. Массового удаления старых данных или пересоздания dev-БД не было.

## Создание и обработка одним запросом

Добавлен основной endpoint Flutter `POST /api/v1/transcripts/process`. Совместимая миграция 0002 хранит неизменяемый хеш исходного запроса. Текст и принятая обработка фиксируются атомарно; используется общий worker с прежним endpoint.

Новые PostgreSQL-тесты проверяют видимость текста и параметров до LLM, отсутствие открытых транзакций, summary, сохранность текста при error, исправление и повтор по ID, одновременные INSERT с одним ключом, конфликт каждого исходного параметра, независимость от порядка папок, общий namespace ключей, rollback при ошибке проверки и восстановление через реальный lifespan после commit без постановки worker.

## Настройки и управление папками

Проверены каждый detail_level, сочетания акцентов, пустые/некорректные инструкции, раздельные роли system/user в запросе Ollama, передача сохранённых настроек worker, конфликт ключа при их изменении и сохранность ручных правок summary. Миграция 0003 добавляет JSONB с default {}, сохраняя текст существующих строк; отдельный PostgreSQL-тест подтвердил это.

По уточнению владельца остаётся только удаление с содержимым, без folder_only/root_only. Проверены пустая папка, вложенное дерево, несколько папок summary, общий источник с summary другого пользователя, будущая внешняя FK-ссылка даже с CASCADE, активная генерация, конкурентные удаления, запрет чужих папок и полный rollback при сбое очистки.
