# Проверка backend MVP

Дата: 2026-10-13. Ветка backend. mobile не изменён, merge в main не выполнен.

## Автоматические проверки

- pytest: 32 успешных теста на API, Ollama MockTransport и настоящем PostgreSQL 18. SQLite не использовался.
- PostgreSQL: миграция на чистую test-БД, downgrade/upgrade, уникальность user + transcript, внешние ключи, идемпотентная инициализация пользователя.
- Конкурентное создание с Idempotency-Key создаёт один transcript; повтор с другим текстом отклоняется.
- Генерация блокирует редактирование, параллельный повтор не вызывает модель второй раз, во время ожидания модели нет idle in transaction.
- Ошибка допускает редактирование до первого успеха; успех навсегда блокирует текст. Удаление summary сохраняет transcript и блокировку.
- Проверены чужие transcript, summary и folders, редактирование summary, несколько папок, замена связей, фильтр и пагинация.
- OpenAPI содержит согласованный набор endpoints; удаления папок пока нет.
- alembic check: расхождений моделей и миграций нет. pip check: конфликты отсутствуют.

## Реальный end-to-end

Через HTTP на loopback, dev PostgreSQL и установленную Ollama-модель `qwen3.8:27b`:

создание папки → сохранение текста и фоновый process одним запросом → идемпотентный повтор → polling ready → получение Markdown-summary → изменение названия и содержания → список по папке → удаление summary → проверка сохранённого заблокированного transcript.

Модель вернула решения, задачу Сергею с указанным сроком и открытый вопрос бюджета. Новые модели не скачивались.

## Практические ограничения

Владелец проекта подтвердил доступ с ПК и физического телефона к 192.168.1.100:8000 при отключённом VPN. Дополнительные изменения Firewall не требуются. VPN в рамках доработки не исследуется.

Один серверный процесс; фоновые задачи не являются устойчивой очередью. После перезапуска доступен явный повтор. Длинные тексты и нагрузка GPU отдельно не проверены; контекст модели может быть меньше символьного лимита API. Нет авторизации, удаления папок, ASR, sharing и автоматического разбиения длинных текстов.

E2E-скрипт оставляет тестовые folders/transcripts в dev-БД; summary удаляет. Это ожидаемые диагностические данные, не пользовательские встречи.

## Создание и обработка одним запросом

Добавлен основной endpoint Flutter `POST /api/v1/transcripts/process`. Совместимая миграция 0002 хранит неизменяемый хеш исходного запроса. Текст и принятая обработка фиксируются атомарно; используется общий worker с прежним endpoint.

Новые PostgreSQL-тесты проверяют видимость текста и параметров до LLM, отсутствие открытых транзакций, summary, сохранность текста при error, исправление и повтор по ID, одновременные INSERT с одним ключом, конфликт каждого исходного параметра, независимость от порядка папок, общий namespace ключей, rollback при ошибке проверки и восстановление через реальный lifespan после commit без постановки worker.
