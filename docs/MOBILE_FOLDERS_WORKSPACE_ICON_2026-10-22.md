# Папки, пространство и иконка: 22 октября 2026

Ветка mobile, отдельный worktree YourMettings-mobile. Backend и main не менялись. Использован существующий docs/API_CONTRACT.md: POST /folders с parent_id, GET /folders с рекурсивным children, GET /summaries с folder_id только для непосредственного содержимого.

## Причины и исправления

1. Родительская папка использовала ExpansionTile: нажатие на название раскрывалось вместо открытия, а открытие summary было отдельным непонятным значком article. Теперь нажатие на название любой папки открывает её содержимое. Отдельная стрелка раскрывает только дерево, не запрашивая summary. Значок article убран.
2. Экран папки показывал только summary, без дочерних папок, и устаревающий объект Folder. Теперь непосредственные подпапки и summary показаны вместе, есть явная кнопка «Создать подпапку». Папка разрешается по UUID из свежего дерева контроллера, поэтому создание/удаление отражается на уже открытом экране. Старое пояснение про отдельное открытие удалено. Удаление по-прежнему требует прежнего подтверждения и использует актуальное поддерево.
3. В выборе папок создание всегда было корневым, а дерево отдельного контроллера аудиопроверки могло устареть. Парсер children уже работал, менять формат API не требовалось. Выбор теперь запрашивает свежее дерево при каждом открытии и сохраняет выбранные UUID. Можно выбрать папку любой глубины; полный путь показан в списке. У каждой папки есть действие создания подпапки. В общем диалоге создания явно выбирается расположение, по умолчанию — текущая папка или верхний уровень. Новая папка выбирается автоматически, прежний выбор сохраняется.
4. GET, начатый до POST создания, мог вернуть старое дерево и перекрыть обновление. Контроллер теперь дожидается текущего GET, затем выполняет свежее чтение после POST. Ошибка создания оставляет введённое имя и родителя в диалоге для повтора.
5. «Пространство» стало тремя квадратными плитками: «Черновики», «Шаблоны», «Отправка и доступ». Черновики открывают отдельный список с прежним восстановлением. Два будущих раздела открывают честное сообщение о недоступности; отправка и шаблоны не реализовывались. На узком экране с увеличенным шрифтом плитки переходят в один столбец.

## Реальная проверка на HONOR 400, Android 16

- Перед установкой открыт отформатированный результат прежней встречи, активного микрофона и открытого редактора не было. Установка выполнена с сохранением данных. Контрольная сумма audio-drafts.json до установки и после всех проверок совпала.
- Из списка папок создана отдельная QA-Mobile-Folders, внутри неё явной кнопкой создана Child-Phone. Нажатие на видимое название открывает содержимое, стрелка раскрывает дерево. Подпапка отобразилась без выхода и повторного входа. Создание в открытой папке заранее выбирает её расположение.
- В новой пустой форме введены синтетический тестовый транскрипт (130 символов) и название QA-Nested-Summary. В выборе папок создана Grandchild-Phone внутри Child-Phone. Новая папка автоматически отмечена; затем дополнительно отмечена корневая QA-папка. Форма сохранила полный путь третьего уровня и ровно два выбранных UUID.
- Нажатие «Обработать» отправило существующий процессинг. Transcript 907c75b5-005f-4300-9683-3f65da495e5b перешёл в ready, summary 96bb9765-4775-488b-94e2-83dc0ea7862a получен от Qwen (673 символа Markdown). GET подтвердил folder_ids корневой QA-папки ad42a592-0eb7-4e1e-9485-321200fb0b5e и папки третьего уровня 357a994a-1cc1-41a1-a2e8-06b7c73e6ac0. Сразу после принятия операции локальный исходный текст очищен, ID обработки сохранён.
- Через список папок открыт Grandchild-Phone; в нём виден QA-Nested-Summary, он открывает правильный отформатированный результат. В корневой QA-папке одновременно видны Child-Phone и это summary, поскольку оно явно связано с обеими папками.

После удаления QA summary и transcript вернули 404. Удалены только собственные тестовые объекты. Перед физическим прогоном также отдельно проверено создание/чтение/удаление пустого QA-дерева через существующий API.
