# Flutter: удалённая демонстрация через VPS

## Подключение

HTTPS base URL: **https://194.117.80.169/api/v1**. Health: https://194.117.80.169/health. Сертификат доверенный, выпущен Let's Encrypt на IP; проверку TLS оставлять включённой. Домена/самоподписанного сертификата нет. Во всех запросах, включая health, polling, каталоги и загрузки:

```http
X-Demo-Key: <секрет, введённый пользователем>
```

Значение ключа backend-агент не помещает в документы/репозиторий/APK. На текущем ПК оно находится в приватном `%LOCALAPPDATA%\YourMettings\demo-access-key.txt`. Передать владельцу приложения вручную безопасным способом; не отправлять в аналитические события/логи/URL. Это не шестизначный почтовый OTP и не SMTP-пароль.

Адрес backend и поле скрытого ввода демонстрационного ключа должны меняться в настройках приложения без пересборки. Удалённый профиль — HTTPS URL выше; USB профиль — http://127.0.0.1:8000/api/v1 с ADB reverse, **тоже с X-Demo-Key**. LAN listener8000 отключён намеренно. Desktop проверка через Swagger/OpenAPI также требует этот заголовок; экспорт схемы — docs/openapi.json в backend.

Хранить ключ в защищённом хранилище, привязывая к origin профиля. При смене адреса не отправлять прежний ключ произвольному серверу автоматически; не переносить его при redirect на иной origin. Ввод без автозамены/автокапитализации, можно убрать только внешние пробелы/перенос строки при вставке. Регистр самого ключа сохранять. Не включать в APK/dart-define/скриншоты/диагностический экспорт. Маскировать X-Demo-Key в Dio/HTTP логах.

## Режим доступа

Это общий демонстрационный аккаунт, а не авторизация разных пользователей. Все допущенные устройства видят одни демо-данные. Использовать только вымышленные записи. Старые личные встречи, транскрипты, папки и шаблоны владельца изолированы и в демо не показываются.

GET /auth/me с ключом возвращает user.id=`00000000-0000-0000-0000-000000000002`, role=user, access_mode=demo, email_verified_at=null. Значение demo@yourmettings.invalid — техническое имя, а не подтверждённая почта. Bearer token не заменяет ключ и не переключает аккаунт. Включённый demo mode закрывает request-code/verify-code/refresh/logout →403 auth_unavailable_demo. Экраны почтовой авторизации для демо не использовать. Предыдущая реализация email auth сохранена для будущего включения.

Демонстрационный ключ имеет серверный срок действия и может быть отозван/заменён владельцем. В текущей конфигурации срок — до 29 октября 2026,16:46 по Москве. Не зашивать эту дату в приложение: ориентироваться на ответ сервера. Никакого refresh для demo key нет.

## Ошибки и восстановление

- 401 demo_key_required/demo_key_invalid — запросить/исправить ключ. Не показывать «сервер недоступен».
- 403 demo_access_expired — срок завершён, нужен новый ключ/разрешение владельца.403 auth_unavailable_demo — endpoint почты отключён в этом режиме.
- 429 demo_rate_limited — подождать Retry-After. Бюджеты ошибочных и правильных ключей разделены; правильный ключ не блокируется одними неверными попытками с того же IP.
- 502/503/504, обрыв/timeout — временная недоступность ПК/туннеля/прокси. Сохранять локальное аудио и ID операций; повторять с задержкой 2,4,8…до 30 секунд. Серверный успешный ответ мог потеряться, поэтому новый UUID/Idempotency-Key здесь создавать нельзя.
- 413 — превышен лимит, уменьшать будущие фрагменты; не удалять локальный файл неуспешной загрузки. Другие документированные 409/422 не повторять бесконечно автоматически.

## Запись и аудиофрагменты

Пути/JSON аудиосессий, ASR и Qwen прежние. Запись можно начать без папок. Фрагменты загружаются POST /audio-sessions/{id}/chunks с прежними sequence_number/start_ms/overlap_ms/SHA и бинарным телом. После complete — polling до ready_for_review, просмотр/редактирование текста, явный confirm либо selection API; папки обязательны перед Qwen. Генерация асинхронная.

Не отправлять аудио как base64 JSON. Предпочтителен AAC/M4A: PCM/WAV существенно больше и медленнее на текущем маршруте через VPN. Backend допускает до 32 MiB на фрагмент и прежние ограничения длительности. Демонстрационный нагрузочный тест использует несжатые фрагменты 2,88 MB; это не рекомендуемый формат обычной записи.

Текущий SSH/VPN-канал передаёт большие несжатые фрагменты медленно: контрольные 2,88 MB потребовали около 153 секунд. Для демонстрации разумны AAC-фрагменты 30–60 секунд, если текущая архитектура позволяет; не ломать поддержку серверных target/max. Connect timeout15–20 с; send/read для upload не меньше 300–360 с (прокси ожидает заголовки 5 минут, тело до 10 минут). Polling использует короткие отдельные запросы раз в 2–3 с и может продолжаться во время долгой генерации; не держать один HTTP до конца Qwen.

201 при первом приёме фрагмента и 200 при повторе того же содержимого подтверждают безопасную локальную очистку по прежнему контракту. При повторе сохранять **те же session_id, sequence_number, байты, границы и SHA**. Создание сессии — UUID Idempotency-Key на операцию, уникальный между устройствами; не фиксированная строка. Повтор confirm после потерянного ответа не запускает второй Qwen. Варианты summary/«Готово» остаются прежними.

Разделять локальные профили/кэш/черновики demo и будущих email-пользователей; не отправлять старый личный черновик в общий demo-аккаунт автоматически.

## Приёмка мобильной части

Без изменения TLS trust подключиться с телефона **через мобильный интернет**, ввести URL/ключ, записать короткую синтетическую встречу, дождаться ASR, подтвердить текст и получить Qwen summary. Отдельно проверить отсутствие ключа, неверный ключ, background upload/retry и смену USB/HTTPS. Backend-агент не изменяет mobile branch и не объявляет мобильный сценарий проверенным до такого теста. Подробный серверный результат публикуется в DEMO_REMOTE_RESULT.md.
