# Проверка доступа по LAN 22 октября 2026

Пользователь сообщил, что телефон по LAN не достигает backend. VPN на ПК сейчас необходим, пользователь попросил его не отключать.

## Проверенные факты

- ПК: Ethernet 192.168.1.100/24. HONOR 400: Wi-Fi wlan0 192.168.1.94/24.
- Backend, PID 20084, слушает TCP 8000 на 127.0.0.1 и 192.168.1.100. Локальные GET /health и GET /api/v1/folders возвращают HTTP 200.
- Запрос с ПК к http://192.168.1.100:8000/health завершается таймаутом соединения. Прямая TCP-проверка health с телефона вне Flutter тоже завершается таймаутом.
- В Windows активны маршруты 192.168.1.0/24 через AmneziaVPN (metric 0) и Ethernet (metric 256). Find-NetRoute к телефону 192.168.1.94 и шлюзу 192.168.1.1 выбирает AmneziaVPN, source 10.8.1.61. Это направляет локальный трафик в VPN вместо Ethernet. Наличие дополнительных фильтров VPN отдельно не исследовалось.
- Установленный в начале APK имел SHA256 AF697024D04F9E0B1F02FE0662BF3567A9D6230F4B1D9F1F11DA0FFFC9785DED и API_BASE_URL=http://127.0.0.1:8000/api/v1. Это сборка для adb reverse; без USB она не обращается к ПК.
- Собрана и установлена актуальная LAN-сборка с API_BASE_URL=http://192.168.1.100:8000/api/v1. При пустом adb reverse приложение показало «Сервер не ответил вовремя. Проверьте подключение» на странице папок.
- Затем восстановлена USB-сборка с adb reverse tcp:8000 tcp:8000. При том же включённом VPN приложение успешно загрузило папки сервера. Хеш файла черновиков до и после установок совпал. Перед первой установкой открытая форма была сохранена действием «Сохранить черновик и выйти».

## Вывод

Две независимые причины: установленная ранее сборка требует USB, а прямой LAN-трафик сейчас не проходит при перехватывающем локальную подсеть VPN-маршруте. Проверенные read endpoints backend работают. Основания запрашивать исправления backend отсутствуют. Проверки ASR/Qwen этим диагностическим прогоном не выполнялись.

Окончательное сравнение LAN с отключённым VPN или разрешённой локальной сетью не проводилось: пользователь не может отключить VPN сейчас. Поэтому отдельное влияние VPN-фильтров и других сетевых правил не изолировано. Для LAN с работающим VPN потребуется согласованное исключение локальной подсети из туннеля/блокировки локальной сети. Настройки VPN, маршрутов и брандмауэра не изменялись; backend не перезапускался и не редактировался.
