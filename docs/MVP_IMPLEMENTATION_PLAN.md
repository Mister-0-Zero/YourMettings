# План текущего MVP

Этот документ уточняет объём текущего этапа. Исходные PROJECT_SPEC и ARCHITECTURE описывают целевую систему. Изменения API отражаются в API_CONTRACT.md.

1. Git: отдельный репозиторий YourMettings, ветка backend, origin, .gitignore. Проверка корня, staged diff, push.
2. FastAPI: конфигурация, health, OpenAPI, Windows README. Проверка pytest и HTTP smoke.
3. Зафиксировать API-контракт для Flutter; сравнить endpoints и примеры с реализацией при финальном QA.
4. PostgreSQL: отдельные dev/test базы, SQLAlchemy, Alembic, пять таблиц и тестовый пользователь. Проверка миграций и ограничений на PostgreSQL.
5. Транскрипты: создание, чтение, редактирование и Idempotency-Key. Проверка прав, валидации и повторов.
6. Папки: создание, дерево, переименование. Проверка вложенности и прав.
7. Ollama: интерфейс адаптера и фиксированный prompt. Unit-тесты ошибок и ответа без реальной модели.
8. Фоновая обработка: polling, блокировка строки при переходе состояния, восстановление после перезапуска. Транзакция не удерживается при LLM.
9. Summary: атомарное сохранение, список, чтение, редактирование, удаление и связи с папками. PostgreSQL API-тесты основных правил и конкурентных запросов.
10. Реальный установленный тег Qwen после загрузки: ollama list, конфигурация .env, реальный end-to-end.
11. Windows/LAN запуск, OpenAPI QA, финальная документация.
12. Последующая задача: удаление дерева папок с двумя явными сценариями. Пока endpoints удаления папок нет.

После каждой проверенной небольшой задачи: тесты, commit, push в backend. mobile не изменяется, merge в main не выполняется.

Правило транскрипта: редактирование блокируется во время генерации и навсегда после первого успеха. Ошибка до первого успеха разрешает редактирование. Удаление summary не снимает постоянную блокировку.

Модель — настройка OLLAMA_MODEL. Новые модели автоматически не скачиваются. Без ASR, регистрации, sharing, Redis, Celery и Docker.
