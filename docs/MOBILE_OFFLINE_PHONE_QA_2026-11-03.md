# Приёмка офлайн-записи и очереди на HONOR 400 — 03.11.2026

Проверили основную YourMettings на HONOR 400 с Android 16. Ветка `mobile`. Проверка охватывает запись и восстановление черновиков, ручное и автоматическое сохранение summary, работу с вариантами и папками. Backend и контракт не менялись.

- Исправление фоновой конкуренции: `0.1.6+7` из `4baae21`, `mobile/build/releases/YourMettings-0.1.6+7-queue-handoff-97abced2.apk` (66 033 227 байт), SHA256 `97ABCED260DF0BE2120157405B90B192F2238753D52497958F55667DAD60FB7F`. ## Сбой фонового продвижения и исправление

Перед исправлением WorkManager запускал задания на HONOR, но в наблюдаемом окне локальные записи не переходили из ожидания, пока интерфейс был свёрнут. Отдельно после `am kill` системный журнал показал, что HONOR отклонял запуск задания по `iaware` / `HN_USER_EXPERIENCE`, в том числе после разового запроса диагностического запуска. Это отдельное ограничение системы; запуск команды не считается выполнением Dart-задачи.

В коде воспроизвели конкуренцию: таймер восстановления диктофона каждые две секунды запрашивал право записи даже в свёрнутом приложении и просил текущего владельца очереди уступить. Регрессионный тест удерживает очередь как фоновый worker и на старом коде видит лишний запрос передачи. Теперь пассивная проверка работает только в активном интерфейсе, сначала читает состояние без захвата, а при необходимости восстановления пробует получить свободное владение без вытеснения worker. Перед записью проверяет, что интерфейс ещё активен и указатель запуска не сменился. Явное управление микрофоном сохраняет штатную передачу владения и проверку токена. Серверный API и правила авторизации не менялись.

`flutter analyze` — без замечаний, `flutter test` — **390 прошли**, включая новую регрессию; `flutter build apk --release` — успешно. Анализ и тесты не заменяют проверку устройства. Нативный код не менялся; 12 JVM-тестов относятся к предыдущему этапу.

На исправленной APK существующий QA-текст открыли после обновления, выбрали свою папку, включили отложенную обработку при недоступном backend, свернули приложение и восстановили USB. Ручную кнопку запуска не нажимали. WorkManager штатно выполнил задания до 20:12:39 МСК. До 20:13:58 МСК экран YourMettings оставался свёрнутым. При первом возврате оба собственных текстовых черновика показали «Summary готов к просмотру». Это проверка фонового сценария с текстом; новое автоматическое аудио от начала до конца без открытия приложения на исправленной APK не повторяли.
