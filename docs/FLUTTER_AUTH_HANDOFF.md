# Flutter: обязательная авторизация и отдельные пользователи

Это обязательное изменение перед удалённым доступом. Flutter-код backend-агент не менял. Точные тела/ошибки — [API_CONTRACT.md](API_CONTRACT.md), серверная активация — [AUTH_MIGRATION.md](AUTH_MIGRATION.md). Бизнес-сценарии ASR/Qwen/вариантов сохранены, но теперь требуют Bearer.

1. Экран email: POST /api/v1/auth/request-code с {email}. Допустим точный cbr.ru либо конкретный административный адрес из allowlist сервера; не зашивать личный адрес в Flutter.202 даёт challenge_id/expires_in/resend_after, кода в ответе нет.503 — доставки нет, не показывать «код отправлен».429 — ждать Retry-After. Получение письма дополнительно зависит от принимающего почтового сервера.
2. Экран кода: POST /auth/verify-code с {challenge_id,email,code,remember_me}. Код — строка из шести цифр, 10 минут, пять попыток. Неверный/использованный401, истёкший401, лимит429. Разрешить повторную отправку после60 секунд, сохраняя актуальный challenge_id. Не логировать код.
3.200 возвращает access_token, access_expires_at, expires_in, session_expires_at, persistence, user и только один renewal token. На каждый пользовательский запрос ставить Authorization: Bearer access_token, включая audio chunks/polling/preview/examples и OpenAPI. Не передавать user_id, токены или коды в URL.
4. remember_me=true: persistence=secure_storage, refresh_token, абсолютная сессия30 дней. Сохранять renewal в защищённом хранилище. false: persistence=memory_only, session_token, абсолютная сессия24 часа; все токены и ключи обновления **только в памяти процесса**, без сериализации в состояние/настройки/черновики. При сворачивании, блокировке экрана и фоновой записи процесс продолжает обновление; после его завершения — новый вход. Сервер сам не распознаёт перезапуск Flutter, соблюдение memory-only — обязанность клиента.
5. Один общий refresh на весь клиент: POST /auth/refresh с {refresh_token} либо {session_token}, отдельный Idempotency-Key. Access до15 минут; обновлять заранее по access_expires_at, а также на401 access_token_expired. Все параллельные запросы ожидают одну операцию. Не делать refresh на любой404/403/429 или на session_revoked/expired.
6. При потере refresh-ответа повторить **тот же старый token + тот же key** в течение120 секунд: вернутся те же токены/абсолютные сроки. Сохранить новую пару атомарно, затем отпустить ожидающие запросы. Повтор старого token с новым key или после окна отзывает сессию (401 session_token_reused). Не восстанавливать исходные expires_in от момента ответа-повтора; используйте access_expires_at. После отзыва/абсолютного истечения — новый вход, локальное аудио сохраняется.
7. Повтор chunk после обновления — тот же session_id/sequence_number/bytes/SHA/границы.201 либо подтверждённый200 позволяют прежний порядок локальной очистки;401/сеть/429 не позволяют терять файл. При audio_capacity_exceeded ждать обработки очереди, не создавать дубль записи. Сервер не отменяет уже принятые задания из-за истечения access/logout.
8. Выход: POST /auth/logout с текущим Bearer, включая уже истёкший access, пока серверная сессия не истекла.204 подтверждает отзыв всей текущей семьи access/renewal. До подтверждения сетевой ошибки держать операцию отзыва для повтора в пределах выбранного режима хранения; один локальный сброс не равен серверному выходу. Не переключать аккаунт, оставляя неподтверждённый logout незаметным. Другие устройства не отзываются.
9. GET /auth/me возвращает id/email/role/email_verified_at. Admin имеет те же возможности и только свои данные. Не добавлять admin-панель/просмотр чужих встреч. Чужой UUID404, системный шаблон read-only403. Привязка старых данных выполняется сервером только после OTP владельца, не первым вошедшим пользователем.
10. Разделить локальные настройки, список черновиков, audio-файлы, незавершённые idempotency операции и кэш **по user.id**. Не показывать данные A после входа B; не отправлять черновик A под токеном B. Незапомненная сессия может оставить локальное аудио для того же пользователя после нового входа, но не секреты восстановления входа. Нового серверного CRUD черновиков/настроек не добавлено.

После активации backend старое приложение без входа получит401. Обновление зависимостей и миграция0009 обязательны на backend; VPS/Firewall/VPN пока не меняются. Подключение по USB/LAN остаётся прежним, с Bearer поверх него. Экспорт [openapi.json](openapi.json) доступен для работы без реальной почты; рабочий HTTP endpoint схемы уже защищён.
