# YourMettings: подключение Flutter к backend

**Для текущей удалённой демонстрации сначала применить [FLUTTER_DEMO_HANDOFF.md](FLUTTER_DEMO_HANDOFF.md): HTTPS + X-Demo-Key, общий изолированный demo-аккаунт. Почтовый вход временно отключён, LAN listener закрыт.**

**Будущий обычный режим авторизации:** [FLUTTER_AUTH_HANDOFF.md](FLUTTER_AUTH_HANDOFF.md). При DEMO_ENABLED=false после активации 0009 пользовательские запросы требуют Bearer; прежние сведения о тестовом общем пользователе больше не применяются.

Актуальная ветка — `backend`. Новый сценарий длинных тестов и выбора итогового варианта описан в [FLUTTER_VARIANTS_HANDOFF.md](FLUTTER_VARIANTS_HANDOFF.md). Этот файл — краткая памятка; точные JSON, ограничения и ошибки определены в [API_CONTRACT.md](API_CONTRACT.md). OpenAPI работающего сервера: `http://127.0.0.1:8000/openapi.json`, интерфейс проверки: `http://127.0.0.1:8000/docs`.

## Подключение

- На ПК: `http://127.0.0.1:8000/api/v1`.
- Android Emulator: `http://10.0.2.2:8000/api/v1`.
- Физический телефон по USB: `http://127.0.0.1:8000/api/v1` после настройки ADB reverse. Отладка по USB должна быть включена и устройство авторизовано. После переподключения проверьте reverse заново.
- По LAN: `http://192.168.1.100:8000/api/v1`, если доступен этот адрес ПК и сеть/VPN допускают соединение. Известная проблема VPN не исправлялась. Не меняйте Firewall/VPN/маршруты ради мобильной реализации.

Проверка соединения — `GET /health` **без** `/api/v1`. В demo обязателен X-Demo-Key. HTTP 200 `{"status":"ok"}` подтверждает доступность FastAPI; готовность PostgreSQL/Ollama/ASR проверяет `start-dev.ps1`.

Пример USB-подключения в PowerShell, когда подключено одно авторизованное устройство:

```powershell
& 'D:\tools\android-sdk\platform-tools\adb.exe' devices
& 'D:\tools\android-sdk\platform-tools\adb.exe' reverse tcp:8000 tcp:8000
```

Если устройств несколько, используйте `-s <serial>` для выбранного телефона. Пустой список ADB означает, что USB-соединение для приложения ещё не настроено.

## Что использовать в приложении

1. `GET /folders` — дерево папок; минимум одна папка нужна перед запуском Qwen. Начать аудиозапись можно без папки.
2. `GET /summary-templates` — список системных и своих шаблонов; `is_default` отмечает стандартный. Не копируйте определения встроенных шаблонов в исходники Flutter.
3. Конструктор: `GET /summary-templates/{id}`, `POST /summary-templates`, `PUT /summary-templates/{id}`, `DELETE /summary-templates/{id}`, `POST /summary-templates/{id}/copy`. Системные записи не редактируются: сначала копия.
4. Тест текущего несохранённого конструктора: `POST /template-previews` с inline `template` и `text`; затем polling `GET /template-previews/{id}`. Это техническое задание без обычной встречи и истории. Статусы queued/generating/ready/error; до 15000 слов / 200000 символов / 400000 UTF-8 байт. Результат в PostgreSQL до 1 часа, переживает перезапуск; незавершённый при старте становится error. Передавайте Idempotency-Key. После истечения/отмены —410; сохраняйте локальный черновик и для явного нового теста используйте новый ключ. Лимит 2 генерации общий с кандидатами встреч.
5. Для сравнения шаблонов без сохранения промежуточных результатов используйте `POST /summary-selections` → `POST /summary-selections/{id}/candidates` → polling → `POST /summary-selections/{id}/accept`; детали в новой памятке. Для прежнего однократного сохранения готовый текст: `POST /transcripts/process` с text/title/folder_ids и необязательными template_id/detail_level/focus_areas/additional_instructions. Сохранять отдельно перед обработкой не нужно. Ответ 202; polling `GET /transcripts/{id}/processing`, затем `GET /summaries/{summary_id}`.
6. Аудио: прежние create/chunks/complete/review. Выбор шаблона и папок передавайте в `POST /audio-sessions/{id}/confirm`, вместе с явным подтверждением и SHA проверенного текста. До confirm Qwen не запускается. Старый сценарий записи/ASR не изменён.
7. Summary по-прежнему можно редактировать и удалять. Удаление пользовательского шаблона не удаляет summary и не меняет уже принятую генерацию.

## Совместимость и повторы

- Отсутствие или null template_id выбирает универсальный шаблон. Прежние запросы продолжают работать.
- Для создания встречи/аудиосессии храните Idempotency-Key до подтверждённого ответа. Одинаковый запрос с тем же ключом не создаёт дубль; изменённые параметры дают 409. Явный UUID default и отсутствие template_id — разные исходные параметры; отсутствие и null равнозначны.
- После ошибки обработки повторный идемпотентный POST создания не запускает Qwen заново. Для новой попытки используйте обработку существующего transcript по ID согласно контракту.
- Preview поддерживает Idempotency-Key: сохраняйте ключ до подтверждённого ответа, блокируйте повторное нажатие и опрашивайте полученный ID. Старый ключ не создаёт тест заново после его истечения/отмены.
- Ошибки имеют оболочку `{"error":{"code":"...","message":"...","details":{}}}`. Ошибки фоновой генерации приходят через polling, а не через первоначальный HTTP 202.
- Авторизация через email OTP и Bearer access token обязательна. Для remember_me=false токены только в памяти; см. новую памятку. Тестового общего пользователя/API-обхода больше нет.

## Отображение результата

`content` — Markdown, `template_snapshot` — снимок происхождения (null у старых summary). Не отправляйте служебные поля snapshot в тело создания/обновления шаблона: берите только поля TemplateInput из контракта.

`navigation` содержит id/title/level/heading_index/line_index. Привязывайте ключи виджетов к порядку заголовков и перехватывайте ссылки `#ym-h-N`. Не полагайтесь на GitHub-якоря. После редактирования content используйте новый массив navigation. Цвета остаются настройкой Flutter, в Markdown не записываются.

## Подготовка и запуск сервера

Новому сценарию нужна миграция `0008` и зависимость tokenizers; из backend выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Для запуска используйте существующий ярлык «YourMettings — запуск сервера» или `start-dev.ps1` из корня репозитория. Не поднимайте второй Uvicorn и не запускайте несколько workers. Backend и ASR обслуживает backend-агент; mobile-агент не меняет backend, рабочую БД, Firewall и VPN.

Базовая система шаблонов проверена 192 тестами и двумя реальными вызовами `qwen3.8:27b`; новые проверки выбора/длинных текстов приведены в новой памятке и отчёте. [Отчёт](TEMPLATES_E2E_RESULT.md), [реальный пример](examples/template_universal_result.md). Новый API предоставляет три полных синтетических примера более 5000 слов каждый; окно контекста не расширялось.

Новый сценарий проверен 275 тестами и семью реальными длинными прогонами Qwen, включая три asset-файла Flutter. Реализация и работающий сервер: b6254ae, миграция 0008 применена. [Результаты и ограничения подключения](VARIANTS_E2E_RESULT.md).
