# API-контракт MVP YourMettings

Версия: v1. Контракт для Flutter. Все изменения API сопровождаются изменением этого файла. Удаление папок отложено: endpoints deletion-preview и DELETE folders в MVP отсутствуют.

## Подключение

Base URL: `http://<LAN-IP-ПК>:8000/api/v1`. Для локальных запросов на ПК: `http://127.0.0.1:8000/api/v1`.

OpenAPI: `/openapi.json`, Swagger: `/docs`, доступность процесса: `GET /health` → `200 {"status":"ok"}`. Health не гарантирует доступность БД или LLM.

Все клиенты используют фиксированного серверного тестового пользователя. `user_id` не передаётся и отклоняется как лишнее поле. Авторизация отсутствует; только доверенная LAN. UUID — строки, время — ISO 8601 UTC. Текстовые запросы: `Content-Type: application/json`.

## Endpoints

| Метод | Путь относительно base URL | Назначение | Успех |
|---|---|---|---|
| POST | /transcripts/process | Создать встречу и запустить обработку (основной способ для Flutter) | 202, включая идемпотентные повторы |
| POST | /transcripts | Сохранить текст | 201; 200 при идемпотентном повторе |
| GET | /transcripts/{id} | Прочитать транскрипт | 200 |
| PATCH | /transcripts/{id} | Изменить текст до успешной обработки | 200 |
| POST | /transcripts/{id}/process | Запустить обработку | 202; 200 если результат уже есть |
| GET | /transcripts/{id}/processing | Проверить статус | 200 |
| GET | /summaries | Список summary | 200 |
| GET | /summaries/{id} | Прочитать summary | 200 |
| PATCH | /summaries/{id} | Изменить название/содержание | 200 |
| PUT | /summaries/{id}/folders | Заменить набор папок | 200 |
| DELETE | /summaries/{id} | Удалить summary и его связи | 204 |
| POST | /folders | Создать папку | 201 |
| GET | /folders | Дерево папок | 200 |
| PATCH | /folders/{id} | Переименовать папку | 200 |

## Основной сценарий Flutter: один запрос «Обработать»

Пользователь редактирует текст локально, задаёт название и папки, затем Flutter отправляет `POST /api/v1/transcripts/process`. Отдельное сохранение перед обработкой не требуется. Файл `.txt` Flutter читает как UTF-8 и отправляет его текст этим же запросом; multipart endpoint отсутствует.

Заголовки: `Content-Type: application/json`, рекомендуется `Idempotency-Key: <уникальный ключ операции, например UUID>`.

Тело запроса:

```json
{
  "text": "Иван: согласовали выпуск в пятницу.",
  "title": "Планирование проекта",
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"]
}
```

Текст непустой, не состоит только из пробелов; лимит по умолчанию 100000 символов. Название — 1–200 символов после удаления внешних пробелов. Папки — 1–100 различных UUID существующих папок пользователя. Лишние поля запрещены.

Успешное принятие: HTTP 202. Текст и параметры принятой обработки сохранены одной короткой транзакцией до запуска фоновой генерации. Во время вызова Qwen транзакция не удерживается.

```json
{
  "transcript_id": "d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status": "summarizing",
  "summary_id": null,
  "error": null
}
```

Дальше Flutter опрашивает `GET /api/v1/transcripts/{transcript_id}/processing`. При `ready` поле `summary_id` содержит UUID; результат загружается через `GET /api/v1/summaries/{summary_id}`. При `error` transcript остаётся в БД. До первого успеха можно исправить текст через PATCH и явно повторить обработку через `POST /api/v1/transcripts/{transcript_id}/process` с названием и папками.

### Idempotency-Key нового endpoint

- Необязательная строка длиной 1–128 символов. Flutter сохраняет ключ до получения ответа и использует его при сетевом повторе одной операции.
- Одинаковый ключ и исходные параметры возвращают HTTP 202, тот же `transcript_id` и **текущее** состояние: summarizing, ready, error или not_started. Новый transcript и второй вызов Qwen не создаются, включая конкурентные запросы.
- Повтор после error не запускает генерацию заново; для этого используйте endpoint по известному transcript_id. Повтор после удаления summary также не запускает генерацию.
- Тот же ключ с другим текстом, названием или набором папок: 409 `idempotency_conflict`. Текст сравнивается точно; название сравнивается после удаления внешних пробелов; порядок UUID папок значения не имеет.
- Сравнение использует неизменяемые исходные параметры: позднейшие правки текста, summary или связей с папками не меняют идентичность принятого запроса.
- Ключи общие для обоих endpoints создания: использование одного ключа в `/transcripts` и `/transcripts/process` даёт 409. Не переиспользуйте ключи разных операций.
- Без ключа каждый запрос создаёт отдельный transcript и запускает отдельную обработку. Для сетевых повторов обязательно используйте ключ.
- Ошибка проверки до принятия не сохраняет transcript и не занимает ключ. После commit данные сохраняются даже при сбое до постановки фоновой задачи. На следующем старте сервера незавершённые записи становятся error / processing_interrupted; доступен явный повтор по ID. Это восстановление при перезапуске, не устойчивая очередь.

Ошибки запроса: 404 `not_found` для недоступных папок; 409 `idempotency_conflict`; 413 `text_too_large`; 422 `validation_error`; 503 `llm_not_configured` или `database_unavailable`; 500 `internal_error`. Ошибки генерации после принятия читаются через polling, а не как ошибка первоначального POST.

## Техническое создание транскрипта (совместимость)

```json
POST /transcripts
{"text":"Иван: согласовали выпуск в пятницу."}
```

Необязательный заголовок `Idempotency-Key` (1–128 символов): уникальный ключ клиентской операции. Одинаковые ключ и исходный текст возвращают прежний transcript, даже если его позднее редактировали. Иной исходный текст с тем же ключом: 409 `idempotency_conflict`. Без ключа каждый POST создаёт новый transcript.

Ответ создания/чтения/редактирования:

```json
{
  "id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "text":"Иван: согласовали выпуск в пятницу.",
  "is_locked":false,
  "created_at":"2026-10-13T12:00:00Z"
}
```

`PATCH /transcripts/{id}`: `{"text":"Исправленный текст"}`. Пустой текст запрещён. Лимит по умолчанию 100000 символов, задаётся backend. Большой текст: 413. Этот отдельный POST сохранён для технических сценариев; основной способ Flutter — `/transcripts/process`.

Во время `summarizing` редактирование запрещено (409). После `error`, если успешной обработки ещё не было, снова разрешено. После первой успешной обработки блокировка постоянна, в том числе после удаления summary.

## Обработка существующего транскрипта и polling

```json
POST /transcripts/{id}/process
{"title":"Выпуск продукта","folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}
```

Название: 1–200 символов после удаления внешних пробелов. Нужна хотя бы одна существующая папка пользователя; UUID не повторяются. Шаблон один системный. Модель выбирается сервером через `OLLAMA_MODEL`.

За один запрос можно указать максимум 100 папок.

Ответ запуска (202) и polling (200), одинаковая структура:

```json
{
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status":"summarizing",
  "summary_id":null,
  "error":null
}
```

| Статус | Значение |
|---|---|
| not_started | Обработка не запускалась |
| summarizing | Генерация и сохранение результата |
| ready | Summary сохранён; summary_id содержит UUID |
| error | Генерация прервана; error содержит code и message |

Для `POST /transcripts/{id}/process`: повтор во время обработки возвращает текущий статус (202), не меняет название/папки принятого запроса и не запускает второй вызов. После успеха возвращает существующий результат (200), сохраняя ручные правки. После ошибки повторный POST по ID запускает новую попытку с указанными параметрами. После удаления summary можно создать его заново из неизменяемого исходного текста. Это отличается от идемпотентного повтора `/transcripts/process`, который никогда сам не запускает новую попытку.

При удалении summary состояние становится not_started, но `is_locked` остаётся true. При перезапуске backend незавершённая обработка переходит в error; автоматическая повторная генерация не выполняется. MVP запускается одним процессом Uvicorn, без нескольких workers.

```json
{
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status":"error",
  "summary_id":null,
  "error":{"code":"llm_timeout","message":"Время ожидания модели истекло."}
}
```

## Summary

Ответ GET/PATCH/PUT:

```json
{
  "id":"ae9f4066-891e-43ec-8485-fdd081218cf2",
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "title":"Выпуск продукта",
  "content":"## Решения\nВыпустить продукт в пятницу.",
  "folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"],
  "created_at":"2026-10-13T12:02:00Z",
  "updated_at":"2026-10-13T12:02:00Z"
}
```

Содержание — Markdown-текст. `PATCH /summaries/{id}`: `{"title":"Новое название","content":"Исправленное содержание"}`. Можно передать только одно из полей; null запрещён. Сохранение по явному запросу клиента; Flutter может вызывать PATCH для автосохранения. При конкурентном редактировании действует последнее сохранение.

`PUT /summaries/{id}/folders`: `{"folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}` полностью заменяет связи. Нужна хотя бы одна папка. Для перемещения передайте новую папку вместо прежней; для размещения в нескольких — весь набор.

`GET /summaries?folder_id=<uuid>&limit=20&offset=0` возвращает `{"items":[<summary>],"total":1,"limit":20,"offset":0}`. folder_id необязателен; выбирает непосредственное содержимое папки, без потомков. limit: 1–100; offset: от 0. Сортировка: created_at по убыванию, затем id. Поиск отложен.

DELETE возвращает пустой 204. Повтор DELETE для отсутствующего объекта: 404. Transcript сохраняется.

## Папки

```json
POST /folders
{"name":"Проект","parent_id":null}
```

name: 1–200 символов. parent_id — null или UUID своей папки. Ответ: `{"id":"60f04cf2-6047-4405-a008-a63544d4f357","name":"Проект","parent_id":null}`.

`PATCH /folders/{id}`: `{"name":"Новое имя"}`. Перемещение папок пока отсутствует; циклы через API создать нельзя.

`GET /folders`:

```json
{"items":[{"id":"60f04cf2-6047-4405-a008-a63544d4f357","name":"Проект","parent_id":null,"children":[]}]}
```

Удаление дерева — последующая отдельная задача. Будущий API должен различать сохранение данных и удаление содержимого с подтверждением, учитывая связи с другими папками.

## Ошибки

```json
{"error":{"code":"transcript_locked","message":"Транскрипт недоступен для редактирования.","details":{}}}
```

| HTTP | code | Причина |
|---|---|---|
| 404 | not_found | Объект не существует или недоступен |
| 409 | transcript_locked | Генерация идёт или уже была успешной |
| 409 | idempotency_conflict | Ключ повторён с другими исходными параметрами или в другом endpoint создания |
| 413 | text_too_large | Лимит текста превышен |
| 422 | validation_error | Некорректные поля/UUID, лишние поля |
| 503 | database_unavailable | База временно недоступна |
| 503 | llm_not_configured | Не задан тег модели |
| 500 | internal_error | Непредвиденная серверная ошибка |

Ошибки фоновой обработки доступны через polling: `llm_timeout`, `llm_unavailable`, `llm_invalid_response`, `processing_interrupted`, `processing_failed`. Не возвращаются credentials или внутренний stack trace.

## Поведение Flutter при сетевых ошибках

1. Сохраняйте введённый текст, название, папки и ключ до подтверждённого принятия `POST /transcripts/process`. Используйте стабильный Idempotency-Key для сетевых повторов одной операции.
2. После 202 опрашивайте статус примерно раз в 2 секунды, постепенно увеличивая интервал до 10 секунд. При сворачивании приложения polling можно остановить.
3. Таймаут HTTP не означает ошибку генерации: повторите исходный `/transcripts/process` с тем же ключом, чтобы получить transcript_id, затем проверьте статус. Для явного повторного запуска после error используйте `/transcripts/{id}/process`.
4. При ready загрузите summary по summary_id; при error покажите сообщение и кнопку повторного запуска.
5. Для 409 перечитайте состояние; для 422 покажите ошибку ввода; для 503 используйте ограниченный повтор с задержкой. Не удаляйте локальный ввод при потере сети.
6. Адрес backend задавайте настройкой окружения Flutter. На физическом телефоне localhost указывает на телефон, а не ПК.

Подключение к `http://192.168.1.100:8000/health` с ПК и физического телефона подтверждено владельцем проекта при отключённом VPN. Дополнительные изменения Firewall не требуются; проблему VPN в рамках этой доработки не решаем.
