# API-контракт MVP YourMettings

Версия: v1. Контракт для Flutter. Все изменения API сопровождаются изменением этого файла. По уточнению владельца проекта поддерживается только удаление папки с содержимым; временные токены подтверждения не используются.

## Подключение

Base URL: `http://<LAN-IP-ПК>:8000/api/v1`. Для локальных запросов на ПК: `http://127.0.0.1:8000/api/v1`.

OpenAPI: `/openapi.json`, Swagger: `/docs`, доступность процесса: `GET /health` → `200 {"status":"ok"}`. Health не гарантирует доступность БД или LLM.

Все клиенты используют фиксированного серверного тестового пользователя. `user_id` не передаётся и отклоняется как лишнее поле. Авторизация отсутствует; только доверенная LAN. UUID — строки, время — ISO 8601 UTC. Текстовые запросы: `Content-Type: application/json`.

## Готовый текст в Flutter: один запрос «Обработать»

Пользователь редактирует текст локально, задаёт название и папки, затем Flutter отправляет `POST /api/v1/transcripts/process`. Отдельное сохранение перед обработкой не требуется. Файл `.txt` Flutter читает как UTF-8 и отправляет его текст этим же запросом; multipart endpoint отсутствует.

Заголовки: `Content-Type: application/json`, рекомендуется `Idempotency-Key: <уникальный ключ операции, например UUID>`.

Тело запроса:

```json
{
  "text": "Иван: согласовали выпуск в пятницу.",
  "title": "Планирование проекта",
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"]
}
```

Текст непустой, не состоит только из пробелов; лимит по умолчанию 100000 символов. Название — 1–200 символов после удаления внешних пробелов. Папки — 1–100 различных UUID существующих папок пользователя. Лишние поля запрещены.

Оба endpoints запуска обработки поддерживают необязательные настройки; старый запрос без них продолжает работать:

```json
{
  "text": "Текст совещания...",
  "title": "Совещание по проекту",
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"],
  "detail_level": "normal",
  "focus_areas": ["tasks", "owners", "deadlines"],
  "additional_instructions": "Отдельно выдели поручения Иванову."
}
```

`detail_level`: brief (кратко), normal (стандартно, по умолчанию), detailed (подробно). Это инструкция по содержанию, а не настройка окна контекста.

`focus_areas`: до 6 различных значений tasks, owners, deadlines, decisions, risks, disagreements. По умолчанию []. Дополняют основной шаблон.

`additional_instructions`: строка до 2000 символов после удаления внешних пробелов, по умолчанию ""; пустая строка допустима, null/нестроковые значения и управляющие символы кроме переноса строки/табуляции запрещены (422). Только пожелания к акцентам и изложению. Серверные правила фактической точности, конфиденциальности и формата имеют приоритет. LLM получает только переданный transcript, инструкции и фиксированный серверный prompt; доступа к БД, инструментам и секретам у модели нет.

Настройки и полный снимок выбранного шаблона сохраняются для конкретной попытки, глобальных предпочтений пока нет. Итог — Markdown с заголовками, списками и блоками задач (Ответственный, Срок, Описание), без широких таблиц. Отсутствующие факты не придумываются.

Успешное принятие: HTTP 202. Текст и параметры принятой обработки сохранены одной короткой транзакцией до запуска фоновой генерации. Во время вызова Qwen транзакция не удерживается.

```json
{
  "transcript_id": "d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status": "summarizing",
  "summary_id": null,
  "error": null
}
```

Дальше Flutter опрашивает `GET /api/v1/transcripts/{transcript_id}/processing`. При `ready` поле `summary_id` содержит UUID; результат загружается через `GET /api/v1/summaries/{summary_id}`. При `error` transcript остаётся в БД. До первого успеха можно исправить текст через PATCH и явно повторить обработку через `POST /api/v1/transcripts/{transcript_id}/process` с названием и папками.

### Idempotency-Key нового endpoint

- Необязательная строка длиной 1–128 символов. Flutter сохраняет ключ до получения ответа и использует его при сетевом повторе одной операции.
- Одинаковый ключ и исходные параметры возвращают HTTP 202, тот же `transcript_id` и **текущее** состояние: summarizing, ready, error или not_started. Новый transcript и второй вызов Qwen не создаются, включая конкурентные запросы.
- Повтор после error не запускает генерацию заново; для этого используйте endpoint по известному transcript_id. После удаления summary это правило действует, только если transcript сохранён из-за зависимостей. При физическом удалении transcript ключ также удаляется; дальнейший POST с этим ключом создаст новую операцию.
- Тот же ключ с другим текстом, названием или набором папок: 409 `idempotency_conflict`. Текст сравнивается точно; название сравнивается после удаления внешних пробелов; порядок UUID папок значения не имеет.
- Настройки генерации также входят в идентичность операции: изменение detail_level, набора focus_areas или additional_instructions даёт 409. Порядок акцентов несущественен. Отсутствующие поля равнозначны normal, [] и ""; ключи запросов, принятых до добавления настроек, продолжают работать с этими значениями.
- Сравнение использует неизменяемые исходные параметры: позднейшие правки текста, summary или связей с папками не меняют идентичность принятого запроса.
- Ключи общие для обоих endpoints создания: использование одного ключа в `/transcripts` и `/transcripts/process` даёт 409. Не переиспользуйте ключи разных операций.
- Без ключа каждый запрос создаёт отдельный transcript и запускает отдельную обработку. Для сетевых повторов обязательно используйте ключ.
- Ошибка проверки до принятия не сохраняет transcript и не занимает ключ. После commit данные сохраняются даже при сбое до постановки фоновой задачи. На следующем старте сервера незавершённые записи становятся error / processing_interrupted; доступен явный повтор по ID. Это восстановление при перезапуске, не устойчивая очередь.

Ошибки запроса: 404 `not_found` для недоступных папок; 409 `idempotency_conflict`; 413 `text_too_large`; 422 `validation_error`; 503 `llm_not_configured` или `database_unavailable`; 500 `internal_error`. Ошибки генерации после принятия читаются через polling, а не как ошибка первоначального POST.

## Техническое создание транскрипта (совместимость)

```json
POST /transcripts
{"text":"Иван: согласовали выпуск в пятницу."}
```

Необязательный заголовок `Idempotency-Key` (1–128 символов): уникальный ключ клиентской операции. Одинаковые ключ и исходный текст возвращают прежний transcript, даже если его позднее редактировали. Иной исходный текст с тем же ключом: 409 `idempotency_conflict`. Без ключа каждый POST создаёт новый transcript.

Ответ создания/чтения/редактирования:

```json
{
  "id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "text":"Иван: согласовали выпуск в пятницу.",
  "is_locked":false,
  "created_at":"2026-10-13T12:00:00Z"
}
```

`PATCH /transcripts/{id}`: `{"text":"Исправленный текст"}`. Пустой текст запрещён. Лимит по умолчанию 100000 символов, задаётся backend. Большой текст: 413. Этот отдельный POST сохранён для технических сценариев; основной способ Flutter — `/transcripts/process`.

Во время `summarizing` редактирование запрещено (409). После `error`, если успешной обработки ещё не было, снова разрешено. После первой успешной обработки блокировка постоянна, в том числе после удаления summary.

## Обработка существующего транскрипта и polling

```json
POST /transcripts/{id}/process
{"title":"Выпуск продукта","folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}
```

Название: 1–200 символов после удаления внешних пробелов. Нужна хотя бы одна существующая папка пользователя; UUID не повторяются. Шаблон выбирается через необязательный template_id; без него используется «Универсальное совещание». Модель выбирается сервером через `OLLAMA_MODEL`.

За один запрос можно указать максимум 100 папок.

Ответ запуска (202) и polling (200), одинаковая структура:

```json
{
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status":"summarizing",
  "summary_id":null,
  "error":null
}
```

| Статус | Значение |
|---|---|
| not_started | Обработка не запускалась |
| summarizing | Генерация и сохранение результата |
| ready | Summary сохранён; summary_id содержит UUID |
| error | Генерация прервана; error содержит code и message |

Для `POST /transcripts/{id}/process`: повтор во время обработки возвращает текущий статус (202), не меняет название/папки принятого запроса и не запускает второй вызов. После успеха возвращает существующий результат (200), сохраняя ручные правки даже при других настройках. После ошибки повторный POST по ID запускает новую попытку с указанными параметрами. После удаления summary повтор по ID возможен, только если источник сохранён из-за зависимостей; иначе 404. Идемпотентный повтор `/transcripts/process` возвращает состояние существующего transcript и сам не запускает новую попытку, пока запись с ключом существует.

При удалении последнего summary транскрипт удаляется, если нет других summary, активной обработки и внешних ссылок. Если зависимость сохраняет транскрипт, постоянная блокировка после первого успеха остаётся. При перезапуске backend незавершённая обработка переходит в error; автоматическая повторная генерация не выполняется. MVP запускается одним процессом Uvicorn, без нескольких workers.

```json
{
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "status":"error",
  "summary_id":null,
  "error":{"code":"llm_timeout","message":"Время ожидания модели истекло."}
}
```

## Summary

Ответ GET/PATCH/PUT:

```json
{
  "id":"ae9f4066-891e-43ec-8485-fdd081218cf2",
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "title":"Выпуск продукта",
  "content":"## Решения\nВыпустить продукт в пятницу.",
  "folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"],
  "created_at":"2026-10-13T12:02:00Z",
  "updated_at":"2026-10-13T12:02:00Z"
}
```

Содержание — Markdown-текст. `PATCH /summaries/{id}`: `{"title":"Новое название","content":"Исправленное содержание"}`. Можно передать только одно из полей; null запрещён. Сохранение по явному запросу клиента; Flutter может вызывать PATCH для автосохранения. При конкурентном редактировании действует последнее сохранение.

`PUT /summaries/{id}/folders`: `{"folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}` полностью заменяет связи. Требуется от 1 до 100 различных папок; пустой список запрещён (422). Для перемещения передайте новую папку вместо прежней; для размещения в нескольких — весь набор. Summary без папок не создаются через API.

`GET /summaries?folder_id=<uuid>&limit=20&offset=0` возвращает `{"items":[<summary>],"total":1,"limit":20,"offset":0}`. folder_id необязателен; выбирает непосредственное содержимое папки, без потомков. limit: 1–100; offset: от 0. Сортировка: created_at по убыванию, затем id. Поиск отложен.


DELETE возвращает пустой 204. Повтор DELETE для отсутствующего объекта: 404. После удаления единственного summary обычно удаляется и исходный transcript с техническими данными и Idempotency-Key; GET transcript и polling тогда возвращают 404. Повтор исходного POST с прежним ключом после физического удаления создаст новую операцию — Flutter не должен повторять создание после намеренного удаления.

Если есть другие summary (включая других пользователей), активная генерация или внешние FK-ссылки, transcript сохраняется. Sharing/ACL пока не реализованы; защитная проверка сохраняет любые внешние FK-ссылки, даже с ON DELETE CASCADE. При добавлении sharing его таблицы должны ссылаться на transcripts внешним ключом; правила удаления истёкших/отклонённых запросов будут уточняться вместе с sharing. Не выполняется безусловное каскадное удаление общего источника.

## Папки

```json
POST /folders
{"name":"Проект","parent_id":null}
```

name: 1–200 символов. parent_id — null или UUID своей папки. Ответ: `{"id":"60f04cf2-6047-4405-a008-a63544d4f357","name":"Проект","parent_id":null}`.

`PATCH /folders/{id}`: `{"name":"Новое имя"}`. Перемещение папок пока отсутствует; циклы через API создать нельзя.

`GET /folders`:

```json
{"items":[{"id":"60f04cf2-6047-4405-a008-a63544d4f357","name":"Проект","parent_id":null,"children":[]}]}
```

### Удаление папок

Параметр mode обязателен; единственное поддерживаемое значение — with_contents. Ответ — пустой HTTP 204; отсутствующая/чужая папка — 404. Режима folder_only и переноса в корень нет.


`DELETE /folders/{id}?mode=with_contents&confirm=true` удаляет выбранную папку и всех потомков. Flutter перед запросом показывает подтверждение удаления содержимого; без confirm=true сервер отвечает 422 `confirmation_required`. Связи с папками дерева удаляются. Summary с другой папкой вне дерева сохраняется. Summary, оставшийся без папок из-за удаления, удаляется; далее проверяются зависимости transcript по правилам удаления summary. Summary вне удаляемого дерева не затрагиваются.

Операция выполняется одной транзакцией PostgreSQL: ошибка откатывает связи, папки, summary и очистку transcript целиком. Если удаляемая папка или её потомок участвует в активной генерации, ответ 409 `folder_processing`: дождитесь ready/error и повторите удаление. Это предотвращает появление результата в уже удалённой папке. Переименование, создание дочерних папок, размещение summary и сохранение worker согласованы транзакционной блокировкой; блокировка не удерживается при вызове Qwen.

## Ошибки

```json
{"error":{"code":"transcript_locked","message":"Транскрипт недоступен для редактирования.","details":{}}}
```

| HTTP | code | Причина |
|---|---|---|
| 404 | not_found | Объект не существует или недоступен |
| 409 | transcript_locked | Генерация идёт или уже была успешной |
| 409 | folder_processing | Удаляемая папка используется текущей генерацией |
| 422 | confirmation_required | Режим with_contents без confirm=true |
| 409 | idempotency_conflict | Ключ повторён с другими исходными параметрами или в другом endpoint создания |
| 413 | text_too_large | Лимит текста превышен |
| 422 | validation_error | Некорректные поля/UUID, лишние поля |
| 503 | database_unavailable | База временно недоступна |
| 503 | llm_not_configured | Не задан тег модели |
| 500 | internal_error | Непредвиденная серверная ошибка |

Ошибки фоновой обработки доступны через polling: `llm_timeout`, `llm_unavailable`, `llm_invalid_response`, `processing_interrupted`, `processing_failed`. Не возвращаются credentials или внутренний stack trace.

## Поведение Flutter при сетевых ошибках

1. Сохраняйте введённый текст, название, папки и ключ до подтверждённого принятия `POST /transcripts/process`. Используйте стабильный Idempotency-Key для сетевых повторов одной операции.
2. После 202 опрашивайте статус примерно раз в 2 секунды, постепенно увеличивая интервал до 10 секунд. При сворачивании приложения polling можно остановить.
3. Таймаут HTTP не означает ошибку генерации: повторите исходный `/transcripts/process` с тем же ключом, чтобы получить transcript_id, затем проверьте статус. Для явного повторного запуска после error используйте `/transcripts/{id}/process`.
4. При ready загрузите summary по summary_id; при error покажите сообщение и кнопку повторного запуска.
5. Для 409 перечитайте состояние; для 422 покажите ошибку ввода; для 503 используйте ограниченный повтор с задержкой. Не удаляйте локальный ввод при потере сети.
6. Адрес backend задавайте настройкой окружения Flutter. На физическом телефоне localhost указывает на телефон, а не ПК.

Подключение к `http://192.168.1.100:8000/health` с ПК и физического телефона подтверждено владельцем проекта при отключённом VPN. Дополнительные изменения Firewall не требуются; проблему VPN в рамках этой доработки не решаем.

## Запись аудио во Flutter: ASR → проверка текста → Qwen

Этот сценарий дополняет ввод готового текста. API принимает **законченные независимые файлы**, пока телефон записывает следующий фрагмент. Это не поток PCM/WebSocket и не распознавание по секундам. Микрофоном управляет Flutter.

### 1. Создать аудиосессию

`POST /audio-sessions`, JSON, рекомендуется стабильный `Idempotency-Key` (1–128 символов) для одной записи:

```json
{
  "title": "Совещание по проекту",
  "detail_level": "normal",
  "focus_areas": ["tasks", "owners", "deadlines"],
  "additional_instructions": "Выдели вопросы без решения."
}
```

`text` отсутствует. Название обязательно (1–200 символов после удаления внешних пробелов); Flutter формирует его с датой и временем начала записи. Только при создании аудиосессии `folder_ids` необязателен: отсутствие поля равнозначно `[]`, скрытая папка не создаётся. Если папки указаны, допустимо до 100 различных UUID существующих доступных пользователю папок; повторяющиеся UUID или более 100 элементов — 422, неизвестная/чужая папка — 404. `null` вместо списка запрещён (422). Остальные настройки необязательны и имеют прежние значения по умолчанию; их можно выбрать вместе с папками после транскрибации при confirm.

Успех **201**, повтор ключа с теми же параметрами — **200** и та же сессия. Для идемпотентности запросы без `folder_ids` и с явным `folder_ids: []` считаются одинаковыми в обоих направлениях. Другой набор папок или другие параметры с тем же ключом — **409 idempotency_conflict**. После явного DELETE незавершённой аудиовстречи повтор исходного POST с её прежним ключом и теми же исходными параметрами возвращает **410 audio_session_deleted**, новая сессия не создаётся; другие параметры с этим ключом по-прежнему дают 409. Порядок folder_ids/focus_areas при сравнении несущественен. Конкурентные повторы сериализуются в PostgreSQL. Пространство ключей аудиосессий отдельно от текстовых запросов. Существующие сессии с папками сохраняют прежнее поведение.

Полный пример начального ответа:

```json
{
  "id": "7bc85fb3-d326-428f-b310-41449fc09790",
  "status": "recording",
  "recording_closed": false,
  "expected_chunk_count": null,
  "received_chunk_count": 0,
  "transcribed_chunk_count": 0,
  "missing_sequence_numbers": [],
  "transcript_id": null,
  "transcript_sha256": null,
  "processing": null,
  "parameters": {
    "title": "Совещание по проекту",
    "folder_ids": [],
    "detail_level": "normal",
    "focus_areas": ["tasks", "owners", "deadlines"],
    "additional_instructions": "Выдели вопросы без решения."
  },
  "error_code": null,
  "boundary_warnings": [],
  "chunks": [],
  "worker_status": "ready",
  "chunk_target_seconds": 300,
  "max_chunk_seconds": 360,
  "max_upload_bytes": 33554432,
  "max_overlap_ms": 3000,
  "max_chunks": 240
}
```

`worker_status` может быть `starting`, `ready`, `busy`, `error`, `offline`. `ready/busy` означает свежий heartbeat отдельного worker с загруженными GigaAM и VAD. После 15 секунд без heartbeat показывается offline. При offline приём файлов по-прежнему разрешён: они надёжно ждут worker в БД. Поля лимитов — актуальная серверная конфигурация; Flutter должен использовать их, а не зашивать значения примера.

### 2. Передавать законченные фрагменты

`POST /audio-sessions/{id}/chunks?sequence_number=0&start_ms=0&overlap_ms=0&duration_ms=300032&content_sha256=<sha256>`

Тело — **сырые байты файла**, `Content-Type: application/octet-stream`; не JSON, не Base64 и не multipart. Поля передаются в query:

| Поле | Правило |
|---|---|
| sequence_number | Обязательно; целое от 0, без пропусков в итоговой записи; меньше max_chunks (предел схемы 239) |
| start_ms | Обязательно; начало в общей временной шкале записи, целое ≥0 |
| overlap_ms | Необязательно, по умолчанию 0; длина перекрытия с предыдущим фрагментом, ≤max_overlap_ms |
| duration_ms | Необязательно; фактическая длительность по данным клиента, целое >0; расхождение с декодированием не более 250 мс |
| content_sha256 | Необязательно; 64 строчные hex-цифры SHA256 именно отправленных байтов; рекомендуется для контроля передачи |

Сервер проверяет сигнатуру, декодирует FFmpeg и измеряет реальную длительность; расширению и MIME не доверяет. Поддерживаются M4A/MP4 с аудиодорожкой (рекомендуется Android M4A/AAC), AAC/ADTS, WAV, MP3, FLAC, Ogg. Каждый файл должен иметь собственный корректно завершённый контейнер. Нельзя просто разрезать байты одного M4A. `audio_format` в ответе — имя демультиплексора FFmpeg (`mov` для M4A/MP4).

Успех **201** только после commit байтов, SHA256, метаданных и состояния queued в одной транзакции PostgreSQL:

```json
{
  "accepted": true,
  "safe_to_delete_local": true,
  "chunk": {
    "id": "3cdc3e7a-5d1b-4778-87be-aa773217d9b8",
    "sequence_number": 0,
    "start_ms": 0,
    "overlap_ms": 0,
    "duration_ms": 300032,
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "byte_count": 2400000,
    "audio_format": "mov",
    "status": "queued",
    "text": null,
    "segments": null,
    "attempt": 0,
    "error_code": null
  }
}
```

Пример SHA256 условный; сервер возвращает вычисленный хеш. Только после ответа с `accepted=true` и `safe_to_delete_local=true` телефон может удалить соответствующий локальный файл. При обрыве/таймауте повторите **тот же файл** с теми же номером, start_ms и overlap_ms. Повтор возвращает **200**, тот же chunk.id и его текущее состояние, без новой ASR; это работает и после очистки серверных аудиобайтов. Другие байты или время под тем же номером — **409 chunk_conflict**, замены нет. Конкурентные загрузки одного номера не создают дублей. До commit подтверждения нет; незавершённая загрузка не создаёт задания.

Первый фрагмент имеет start_ms=0 и overlap_ms=0. Порядок доставки произвольный, сборка всегда по sequence_number. ASR выполняется автоматически отдельным worker; HTTP не ждёт распознавания. Состояния фрагмента: `queued → transcribing → done` либо `failed`. `attempt` считает реальные захваты задания, включая восстановление. При done доступны text и segments — список `{start, end, text}` со временем **в секундах относительно начала фрагмента**; для глобального времени прибавьте start_ms/1000. Это границы ASR/VAD-сегментов, не точные таймкоды слов.

### 3. Границы фрагментов

Основной вариант MVP — непрерывная запись, граница по паузе около chunk_target_seconds, без перекрытия. Следующий файл начинается ровно там, где закончился предыдущий; остановка/запуск рекордера с потерей звука между файлами неприемлемы. max_chunk_seconds оставляет запас для поиска паузы; этот механизм обязан реализовать Flutter.

Если выбран перекрывающийся режим, Flutter сохраняет до max_overlap_ms конца предыдущего аудио и включает его в начало следующего. Тогда `start_ms[n] = start_ms[n-1] + duration_ms[n-1] - overlap_ms[n]` с допуском 250 мс на контейнер/округление. В режиме без перекрытия используется та же формула с 0. При несогласованной шкале сборка получает failed/timeline_mismatch; метаданные принятого фрагмента не заменяются — исправьте формирование файлов и создайте новую сессию.

Сборщик удаляет только точное совпадение суффикса/префикса из минимум двух слов, без учёта регистра и пунктуации, в ограниченном окне перекрытия. Если соответствие ненадёжно, оба текста сохраняются, а boundary_warnings содержит `{sequence_number, code: "overlap_not_aligned"}`. Flutter должен показать стык и потребовать его проверки. ASR может по-разному распознать одинаковый звук; гарантировать отсутствие ошибок, потерь слов или повторов на произвольной записи невозможно. Пользователь проверяет полный текст перед Qwen; при неоднозначном стыке автоматическое удаление текста не применяется.

### 4. Завершить запись и дождаться всех частей

`POST /audio-sessions/{id}/complete`, JSON:

```json
{"expected_chunk_count": 2}
```

**202**, полный ответ AudioSessionOut как при создании, но recording_closed=true. Допустимо вызвать до доставки последнего файла или во время ASR. Число — от 1 до max_chunks, означает точный диапазон 0…count−1. Повтор с тем же числом безопасен; другое число или уже принятый номер за пределами диапазона — 409 chunk_count_conflict. Позже можно доставить отсутствующие файлы из диапазона; новые номера вне него — 409 unexpected_chunk.

Polling: `GET /audio-sessions/{id}` каждые 2 секунды, при долгом ожидании до 10 секунд. received_chunk_count — принятые файлы, transcribed_chunk_count — done. missing_sequence_numbers показывает отсутствующие номера **после complete**; до complete список пуст, так как общее число ещё неизвестно. Нет фиктивного процента или оценки оставшегося времени. chunks упорядочен по номеру и содержит данные каждого фрагмента в формате выше. Время обработки фрагментов не обязано совпадать с порядком их поступления.

| status | Значение |
|---|---|
| recording | Запись не закрыта; файлы поступают, ASR уже может идти (смотрите chunks/worker_status) |
| transcribing | Complete принят, ждём отсутствующие/нераспознанные части |
| ready_for_review | Все части done, единый transcript сохранён; Qwen ещё не запускался |
| failed | Ошибка фрагмента или сборки; готовые части сохранены |
| completed | Проверка подтверждена и принята существующая обработка Qwen; её статус отдельно в processing |

transcript_id появляется только после complete и успешной сборки **всех** частей, один на сессию. processing тогда содержит обычный ProcessingOut, сначала not_started; transcript_sha256 — SHA256 текущего текста UTF-8, включая пользовательские правки.

ASR-повтор: `POST /audio-sessions/{id}/retry`, JSON `{}` для всех failed либо `{"sequence_numbers":[1]}` для выбранных номеров (список 1–240 целых 0–239). Ответ 200 AudioSessionOut. Повтор переводит только failed в queued, не трогает done/активные задания и не запускает Qwen. Неизвестный номер — 404; завершённая сборка возвращается без изменений. Для незаявленных/недоставленных частей нужна загрузка, не retry. Ошибки сборки empty_transcript/transcript_too_large/timeline_mismatch не исправляются повтором тех же готовых частей: проверьте аудио, лимиты и временную шкалу.

### 5. Просмотр, правка и явное подтверждение

После ready_for_review загрузите `GET /transcripts/{transcript_id}` и покажите **полный** текст. Правки сохраняются через существующий `PATCH /transcripts/{transcript_id}` с `{"text":"Исправленный полный текст"}`. Затем перечитайте аудиосессию для актуального transcript_sha256. `POST /transcripts/{id}/process` до подтверждения аудиосессии отклоняется 409 audio_review_required.

Кнопка «Подтвердить и создать summary» отправляет `POST /audio-sessions/{id}/confirm`:

```json
{
  "confirm": true,
  "reviewed_text_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "boundaries_reviewed": true,
  "title": "Совещание по проекту",
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"],
  "detail_level": "normal",
  "focus_areas": ["tasks", "owners", "deadlines"],
  "additional_instructions": "Выдели вопросы без решения."
}
```

Используйте реальный hash из последнего GET, условный hash примера непригоден. confirm=true обязателен; boundaries_reviewed по умолчанию false, при наличии boundary_warnings требует явного true после проверки стыков. Название и **от 1 до 100 различных существующих доступных папок** обязательны при confirm, в том числе если запись начата без папок. Отсутствие folder_ids или [] здесь возвращает 422. Настройки по тем же правилам, что в ProcessInput; можно передать параметры, выбранные пользователем на экране проверки. Если папка удалена за время записи, выберите существующую перед подтверждением. Послабление создания аудиосессии не применяется к текстовым endpoints и размещению summary.

Ответы POST /audio-sessions и GET /audio-sessions/{id} всегда содержат parameters.folder_ids, в том числе [] для записи без папок. После принятого confirm в parameters отражаются подтверждённые папки и настройки.

**202 ProcessingOut**:

```json
{"transcript_id":"b8f031c6-3348-46ab-a5b5-c64a9f7fcda2","status":"summarizing","summary_id":null,"error":null}
```

Подтверждение и параметры Qwen фиксируются до вызова LLM. При изменении текста между просмотром и подтверждением — **409 review_outdated**: перечитайте и снова покажите текст. Повтор confirm после принятия, в том числе конкурентный, возвращает **200** с текущим ProcessingOut, не меняет параметры и не запускает Qwen заново. Сессионный Idempotency-Key на confirm не нужен.

Дальше обычный `GET /transcripts/{id}/processing`, при ready — `GET /summaries/{summary_id}`. completed у аудиосессии не означает готовность summary. При ошибке LLM исходный текст сохранён; повторите существующий `POST /transcripts/{id}/process` с параметрами. Повтор confirm сам по себе ошибку LLM не перезапускает. Блокировка текста прежняя: во время генерации; навсегда после первого успеха; после ошибки до первого успеха редактирование разрешено. Summary можно редактировать обычным PATCH.

### Надёжность, восстановление и ошибки аудио

Временный файл HTTP используется только для загрузки/проверки. Надёжное хранилище MVP — аудиобайты BYTEA в PostgreSQL вместе с метаданными и queued в **одном commit**, что устраняет несогласованность файловой системы и БД. После успешного ASR текст/таймкоды и удаление payload фиксируются одной транзакцией; hash/метаданные остаются для повторных запросов. Ошибочные/ожидающие задания сохраняют payload. Отдельный worker делает только временную рабочую копию; она удаляется после работы, остатки в его выделенной .runtime/asr очищаются следующим владельцем worker. PostgreSQL освобождает место удалённых значений для повторного использования штатно; файл БД не обязан сразу уменьшаться.

Перезапуск FastAPI не сбрасывает ASR-очередь и не останавливает отдельный worker. При старте worker единственный владелец возвращает transcribing в queued, продолжает обработку, не трогая done/failed. Windows mutex и PostgreSQL advisory lock исключают второй worker; generation/attempt блокируют запись устаревшего результата. При потере связи с БД worker останавливается, оставляя задания для восстановления; повторно запустите штатный launcher. Дочерний ASR-процесс следит за жизнью своего координатора и освобождает CUDA при его аварийном завершении. Это восстановление **после запуска процесса**, не Windows-служба с автоперезапуском. Qwen при перезапуске backend сохраняет прежнее поведение error/processing_interrupted с явным повтором.

| HTTP | code | Действие Flutter |
|---|---|---|
| 404 | not_found | Перечитать доступные объекты; сессия/папка/номер не найдены |
| 409 | idempotency_conflict / chunk_conflict | Не заменять данные молча; проверить ключ/номер/время/файл |
| 409 | session_closed / unexpected_chunk / chunk_count_conflict | Перечитать сессию и ожидаемый диапазон |
| 409 | transcript_not_ready / audio_review_required | Дождаться сборки и пройти экран проверки |
| 409 | review_outdated / boundary_review_required | Перечитать текст, проверить стыки, подтвердить заново |
| 409 | audio_unavailable | Исходное аудио отсутствует для повтора; требуется диагностика |
| 413 | audio_too_large / audio_too_long | Уменьшить размер/длительность будущих фрагментов |
| 422 | invalid_audio / audio_validation_timeout | Не удалять локальный файл, проверить запись/кодек |
| 422 | checksum_mismatch / duration_mismatch | Проверить байты и длительность перед повтором |
| 422 | invalid_chunk_parameters / invalid_chunk_count / validation_error | Исправить поля и сверить лимиты |
| 422 | confirmation_required | Требуется явное подтверждение |
| 503 | asr_not_configured / database_unavailable | Сохранить локальный файл, сообщить о настройке сервера, повторить с задержкой |

Фоновые chunk.error_code: asr_gpu_memory, asr_transcription_failed. Сессионные: chunk_failed, timeline_mismatch, empty_transcript, transcript_too_large. При worker_status=offline/error серверный launcher проверяет окружение, модели, VAD и GPU; телефон хранит непринятые локальные файлы. `/health` не проверяет ASR.

ASR и Qwen по умолчанию выполняют GPU-операции последовательно через общий advisory lock (`ASR_GPU_SERIAL=true`), без транзакции на время вычислений. Модели остаются резидентными; последовательность не гарантирует вместимость любых моделей в VRAM. Backend не выгружает Ollama, не скачивает веса и не завершает чужие GPU-процессы. Настройка false снимает этот межкомпонентный лимит, но worker всё равно последовательный; менять её следует только после замера памяти/нагрузки.

Удаление последнего summary по прежним правилам удаляет неиспользуемый transcript и completed-аудиосессию с её метаданными. Для ready_for_review предусмотрено отдельное подтверждённое удаление ниже. Незавершённые аудиосессии не очищаются автоматически по таймеру, чтобы не терять ожидающие/ошибочные записи. Архивирование исходного аудио в этот MVP не входит.

### 6. Удаление незавершённой аудиовстречи

После ASR Flutter может сохранить локальный черновик и выйти: это не требует DELETE или нового серверного CRUD. Позже можно открыть ту же сессию и продолжить правку. Для действия **«Удалить встречу»** Flutter сначала показывает отдельное подтверждение, затем вызывает:

```http
DELETE /api/v1/audio-sessions/7bc85fb3-d326-428f-b310-41449fc09790?confirm=true
```

JSON-тело и Idempotency-Key для DELETE не требуются. Обязателен query-параметр confirm со значением true. Отсутствие/false — **422 confirmation_required**, некорректный UUID или boolean — **422 validation_error**; ничего не удаляется. При отсутствии подтверждения возвращается 422 даже для неизвестного ID. При confirm=true проверяется принадлежность текущему серверному пользователю; неизвестная и чужая сессия одинаково возвращают **404 not_found**.

Допустимо только **ready_for_review**: запись закрыта, все заявленные номера присутствуют, все chunks=done, единый transcript существует, принадлежит пользователю, не используется техническим текстовым сценарием, processing.status=not_started, processing_attempt=0 и успешной генерации прежде не было. Summary либо внешние ссылки на transcript/session/chunk препятствуют удалению. Поддержка recording, transcribing, failed и completed этим endpoint **не реализована**; возвращается **409 audio_session_not_deletable**, данные сохраняются. Если уже принят confirm, даже если Qwen ещё выполняется или завершился ошибкой, этот DELETE запрещён. Completed-встречи по-прежнему удаляются через summary, с прежними правилами сохранения общего источника; создавать summary ради удаления черновика не нужно.

Первое успешное удаление возвращает **204 No Content**, пустое тело. В одной транзакции PostgreSQL удаляются аудиосессия, её chunks (включая BYTEA, тексты, таймкоды, ошибки/attempt/claim и очередь ASR), принадлежащий только этой сессии неиспользуемый transcript. Папки, другие встречи/summary и общий ASR-worker не удаляются. Внешние FK-зависимости, включая CASCADE и составные ссылки, консервативно дают **409 audio_session_in_use**, а не удаляются вместе с объектом. Состояние «готово» с незавершёнными частями/запущенным Qwen также даёт 409 audio_session_not_deletable.

Одновременно сохраняется минимальная **квитанция удаления**: UUID сессии, user_id, исходный Idempotency-Key (если был), неизменяемый hash исходных параметров и время. В ней нет аудио, текста, названия, папок или настроек. Она не является черновиком/аудиосессией, не выдаётся через GET, не истекает автоматически и нужна для безопасных повторов и запрета восстановления удалённой встречи старым POST.

| Повтор после успешного DELETE | Результат |
|---|---|
| DELETE того же ID с confirm=true тем же пользователем | **204**, в том числе после потери первого ответа и перезапуска backend |
| DELETE неизвестного ID или ID другого пользователя, включая чужую квитанцию | **404 not_found** |
| GET /audio-sessions/{id}, GET/PATCH его удалённого transcript | **404 not_found** |
| confirm, upload, complete или retry удалённой сессии | **404 not_found** для корректного запроса |
| POST /audio-sessions с прежним ключом и прежними исходными параметрами | **410 audio_session_deleted**, не 200/201 |
| POST с прежним ключом и изменёнными исходными параметрами | **409 idempotency_conflict** |
| POST с новым ключом | Новая независимая запись, обычные правила 201 |

Для Flutter стабильный ключ создания обязателен на уровне клиентского сценария: храните его вместе с ID черновика до принятия решения об удалении. Отсутствие folder_ids и [] остаются эквивалентными и после удаления; правки transcript не меняют исходный hash. Ключ без квитанции продолжает работать по прежним правилам. Сам заголовок на сервере остаётся необязательным для совместимости: **POST без ключа всегда означает новую операцию**, его нельзя безопасно повторять после сетевой ошибки/намеренного удаления. Прежний сценарий удаления completed-встречи через summary и срок жизни его ключей этим изменением не меняются.

Пример ошибки старого POST:

```json
{"error":{"code":"audio_session_deleted","message":"Эта аудиовстреча намеренно удалена; начните новую запись с новым ключом.","details":{}}}
```

**Конкуренция.** DELETE, confirm, retry, complete и запись принятого upload используют общую транзакционную блокировку пользователя и блокировку сессии. Если DELETE победил confirm, confirm получает 404 и Qwen не вызывается. Если confirm первым зафиксировал completed, DELETE получает 409, принятая обработка и её результаты сохраняются. При одновременных DELETE первый удаляет, второй получает 204 по квитанции. Старый POST после commit удаления получает 410; он не восстанавливает объект.

Отдельная shared advisory-блокировка на время HTTP-загрузки/проверки аудио держит соединение, **не транзакцию**, и освобождается при успехе, ошибке или прерывании. Если upload уже выполняется, DELETE возвращает **409 audio_session_busy**, без удаления строк БД. Если DELETE получил исключительную блокировку раньше нового upload, upload после commit удаления получает 404 и не создаёт фрагмент. После ошибки/прерывания загрузки можно повторить DELETE. ASR-результат сохраняется только для существующих session/chunk с актуальными generation/attempt/status; поздний результат удалённого задания отклоняется, восстановление worker не создаёт удалённые строки заново.

**Файлы и граница гарантии 204.** Авторитетные аудиобайты находятся в PostgreSQL, не в файловом хранилище. Рабочие ASR-копии находятся только в backend/.runtime/asr/job-{session_id}-*; декодирование вложено в каталог задания, очищается до выдачи результата, весь каталог задания — до фиксации done/ready_for_review. DELETE дополнительно очищает остаточные каталоги именно этой сессии, проверив их расположение; общую .runtime/asr, каталоги других сессий, модели и пользовательские файлы не очищает.

Очистка проводится после всех проверок и до commit удаления. Эти копии готовых заданий не нужны для восстановления: текст/таймкоды уже находятся в PostgreSQL. Если очистка не удалась или путь небезопасен — **409 audio_cleanup_failed**, строки БД и ключ создания остаются; часть ненужных временных копий может быть уже удалена. Если commit не прошёл, удаление БД и квитанция откатываются; потеря только ненужной копии не теряет исходный transcript. Нормальный **204 означает, что перечисленные строки удалены commit-ом, известные рабочие копии сессии очищены и квитанция сохранена**; асинхронной незавершённой очистки после 204 нет. При потере ответа повторите DELETE, а не создание встречи.

Другие ошибки: **503 database_unavailable** — БД временно недоступна; **500 internal_error** — непредвиденный сбой, результат следует уточнить повторным подтверждённым DELETE. При сетевой ошибке, 409, 422, 503 или 500 Flutter сохраняет локальные данные и ID/ключ для повтора; локальные аудиофайлы/черновик удаляются только после 204. Не интерпретируйте произвольный 404 DELETE как подтверждённое удаление: успешный повтор гарантирован именно квитанцией и возвращает 204.

Для развёртывания нужна аддитивная миграция **0005** и плановый перезапуск backend и ASR-worker (привязка/порядок очистки рабочих каталогов). После обновления ASR-worker штатно очищает старые общие временные копии при старте под своей singleton-блокировкой. Работающие процессы этой доработкой автоматически не перезапускаются.


## Шаблоны генерации: контракт Flutter

Маршруты ниже имеют общий префикс `/api/v1`. Существующая авторизация не меняется: MVP использует серверного тестового пользователя. Системные шаблоны видны всем; пользовательские — только владельцу. Это пока не многопользовательский сервер с login.

### Каталог и конструктор

`GET /summary-templates` → 200 `{"items": [Template, ...]}`. Сначала шаблон по умолчанию, затем системные и пользовательские. `GET /summary-templates/{id}` → 200 Template; неизвестный/чужой UUID → 404 `not_found`.

Пример **тела создания или полной замены** (TemplateInput):

```json
{
  "name": "Решения команды",
  "description": "Решения и тематические задачи",
  "structure_mode": "strict",
  "general_instructions": "Сохраняй названия сервисов и явно согласованные действия.",
  "sections": [
    {
      "id": "10000000-0000-4000-8000-000000000001",
      "title": "Общие итоги",
      "instruction": "Изложи общие результаты встречи.",
      "position": 0,
      "required": true,
      "type": "section",
      "children": []
    },
    {
      "id": "10000000-0000-4000-8000-000000000002",
      "title": "Темы",
      "instruction": "Выдели самостоятельные темы. Объедини повторные обсуждения одной темы.",
      "position": 1,
      "required": true,
      "type": "repeated",
      "children": [
        {
          "id": "10000000-0000-4000-8000-000000000003",
          "title": "Решения и задачи",
          "instruction": "Сохрани принятые решения, задачи, названных ответственных и сроки.",
          "position": 0,
          "required": true,
          "type": "section",
          "children": []
        }
      ]
    }
  ]
}
```

Template в ответе содержит все эти поля, а также `id`, `owner_user_id` (null для системных), `is_system`, `is_default`, `created_at`, `updated_at` (ISO 8601). Эти служебные поля **не передаются** при POST/PUT или внутри inline preview. Flutter может взять изменяемые поля из GET и редактировать их локально. UUID раздела создаётся клиентом один раз и сохраняется при редактировании/перестановке; UUID самого шаблона создаёт сервер.

- `POST /summary-templates` + TemplateInput → 201 Template.
- `PUT /summary-templates/{id}` + полный TemplateInput → 200 Template. Пропущенные необязательные поля получают значения по умолчанию; это полная замена, не PATCH.
- `DELETE /summary-templates/{id}` → 204; повтор после удаления → 404. Ранее созданные summary и принятые попытки обработки остаются со своими снимками.
- `POST /summary-templates/{id}/copy` + `{"name":"Мой вариант"}` → 201 пользовательский Template. Тело можно опустить или передать `{}`: имя получает суффикс « (копия)». UUID шаблона новый; UUID разделов внутри копии сохраняются. Копирование доступно для системного и своего шаблона.
- PUT/DELETE системного шаблона → 403 `template_read_only`. Неизвестный/чужой шаблон для всех операций → 404 `not_found`. Ошибки схемы → 422 `validation_error`; недоступная БД → 503 `database_unavailable`.

Ограничения: name/title 1–200 символов после trim; description ≤2000 (по умолчанию пустая); general_instructions ≤8000 (по умолчанию пустая); instruction каждого раздела 1–4000 после trim. Верхних разделов 1–20, вложенных у repeated 1–12, всего ≤100. Два уровня: обычный `section` не имеет детей; `repeated` имеет только обычные дочерние разделы. Инструкция repeated описывает выделение тем. В пределах одного шаблона все UUID разделов уникальны. `position` — целое число с нуля, подряд, в порядке массива на каждом уровне. `required` по умолчанию true, `type` по умолчанию section, `children` по умолчанию []. Неизвестные поля, типы, пустые инструкции, повторные UUID и чрезмерная вложенность запрещены.

`structure_mode` по умолчанию strict: только предусмотренные разделы верхнего уровня в заданном порядке. flexible сохраняет основные разделы и порядок, допускает дополнительные тематические разделы **после** них. Обязательные разделы выводятся всегда; отсутствующие данные — точная строка «Не указано». Необязательный раздел может отсутствовать; если включён, но пуст, также «Не указано». Для обязательного repeated без найденных тем выводится его заголовок и «Не указано», без выдуманной темы. Один repeated допускает до 40 найденных тем; flexible — до 10 дополнительных верхних разделов. Текст одного раздела ответа ограничен 150000 символами; нарушение лимита/структуры ответа даёт llm_invalid_response.

Серверные правила едины и не редактируются: только факты исходного текста; сохранение имён, чисел, сроков и терминов; разделение предложений и окончательных решений; объединение повторных обсуждений; без широких таблиц, HTML/CSS и цветов. Это инструкции модели, а не автоматическая проверка достоверности каждого факта. Backend технически проверяет структуру и сам собирает Markdown; некорректный ответ Qwen приводит к `llm_invalid_response`.

### Системные UUID

| UUID | Название | Режим |
|---|---|---|
| 019a0120-0000-7000-8000-000000000001 | Универсальное совещание (default) | strict |
| 019a0120-0000-7000-8000-000000000002 | Протокол совещания | strict |
| 019a0120-0000-7000-8000-000000000003 | Краткое содержание встречи | strict |
| 019a0120-0000-7000-8000-000000000004 | Рабочая планёрка | strict |
| 019a0120-0000-7000-8000-000000000005 | Проектная встреча | strict |
| 019a0120-0000-7000-8000-000000000006 | Мозговой штурм | flexible |
| 019a0120-0000-7000-8000-000000000007 | Переговоры и договорённости | strict |

Семь записей создаются миграцией и идемпотентной проверкой при старте. Повторный старт не создаёт копии. Для конструктора Flutter загружает актуальные разделы через GET, не дублирует их определения в приложении. У универсального шаблона четыре верхних раздела: Общая информация, Содержание, Тематический разбор, Общие итоги; repeated содержит восемь подразделов на каждую тему.

### Выбор для текстовой и аудиовстречи

```json
POST /transcripts/process
{
  "text": "Анна: решили выпустить API 3 ноября. Борис: тест отката сделаю к 28 октября.",
  "title": "Планирование выпуска",
  "folder_ids": ["60f04cf2-6047-4405-a008-a63544d4f357"],
  "template_id": "019a0120-0000-7000-8000-000000000005",
  "detail_level": "normal"
}
```

Необязательное `template_id` поддерживается `/transcripts/process`, `/transcripts/{id}/process` и `/audio-sessions/{id}/confirm`. Без поля или при null применяется универсальный системный шаблон. На confirm шаблон выбирается перед Qwen; папка, SHA проверенного текста и явное подтверждение по-прежнему обязательны. Аудиозапись, ASR и review от выбора шаблона не запускают Qwen и не меняются. В начальном POST `/audio-sessions` поле тоже допускается как предварительный параметр, но окончательный выбор определяется телом confirm.

Нужный Template читается с блокировкой и полностью сохраняется в `processing_options.template_snapshot` одной короткой транзакцией с принятием обработки. Изменение/удаление каталога после принятия не влияет на выполняемую попытку. После ошибки явный повтор по ID может выбрать другой шаблон. Неизвестный/чужой template_id при принятии → 404, без создания встречи/запуска модели. Идемпотентный повтор уже принятого запроса возвращает его состояние даже после удаления шаблона.

Выбранный UUID входит в идемпотентность запроса: другой template_id с тем же Idempotency-Key → 409. Отсутствие и null равнозначны. Явный UUID default считается отдельным исходным параметром и не равнозначен его отсутствию. Позднее редактирование шаблона не меняет идентичность уже принятого запроса. Старые ключи текстовых/аудиозапросов и квитанций удаления сохраняют прежнее поведение при отсутствии/null template_id.

`detail_level` — прежний brief/normal/detailed. Brief сжато раскрывает каждую тему; normal раскрывает существенные аргументы и результаты; detailed добавляет позиции, альтернативы и детали без повторов. Все уровни сохраняют важные решения, задачи, ответственных и сроки. Объём зависит от содержания; фиксированного числа предложений нет. `focus_areas` и `additional_instructions` продолжают работать в пределах серверных правил.

### Preview текущего черновика, без встречи

`POST /template-previews` принимает весь тестовый текст и inline TemplateInput. Рекомендуется `Idempotency-Key` (1–128 символов), сохраняемый до подтверждённого ответа:

```json
{
  "text": "Анна: подготовлю инструкцию к 29 октября. Решение принято.",
  "template": {
    "name": "Ещё не сохранённый шаблон",
    "structure_mode": "strict",
    "sections": [{
      "id": "10000000-0000-4000-8000-000000000003",
      "title": "Поручения",
      "instruction": "Выдели утверждённые поручения, ответственных и сроки.",
      "position": 0, "required": true, "type": "section"
    }]
  },
  "detail_level": "normal", "focus_areas": [], "additional_instructions": ""
}
```

Используется именно inline template, включая несохранённые изменения. Служебные id/is_system/owner_user_id/timestamps каталога в template не передаются. Лимит прежних 12000 символов заменён: теперь непустой исходный текст до **15000 слов, 200000 символов и 400000 байт UTF-8 одновременно**, без обрезки. Количество слов — `len(text.split())`. Превышение схемного max_length текста даёт 422, слов/байтов —413 source_too_large. Настройки и правила конструктора прежние.

Ответ POST202 и polling `GET /template-previews/{id}`200:

```json
{
  "id": "74086f9e-ac43-415e-a5f7-a499a1fa79bd",
  "status": "queued",
  "content": null,
  "navigation": [],
  "template_snapshot": {"name":"Ещё не сохранённый шаблон","description":"","structure_mode":"strict","general_instructions":"","sections":[]},
  "generation_options": {"detail_level":"normal","focus_areas":[],"additional_instructions":""},
  "processing_metadata": {},
  "error": null,
  "expires_at": "2026-10-23T21:00:00Z"
}
```

В этом сокращённом примере template_snapshot.sections показан пустым только для компактности ответа: фактически сервер возвращает полную принятую структуру из запроса. Статусы queued → generating → ready/error. При ready content — Markdown, navigation — актуальные заголовки. В processing_metadata передаются стратегия direct/hierarchical, размеры источника, число частей и этапов и сведения о проверке контекста. При error поле error.code/message содержит llm_timeout, llm_unavailable, llm_invalid_response, context_limit_exceeded, processing_interrupted либо processing_failed.

Preview теперь хранится в **отдельных технических PostgreSQL-таблицах**, без создания обычных Transcript/Summary/Folder/AudioSession и без пользовательской истории. Сохраняются исходный тестовый текст и результат на срок не более **1 часа**; очистка выполняется при обращениях и фоново раз в 60 секунд. По истечении срока payload очищается; остаются только служебные сведения/хеши для защиты повторов. Одновременно сохраняется до 20 открытых previews: самый старый завершённый может быть очищен раньше. Лимит генераций общий с кандидатами встреч:2 queued/generating на пользователя. Превышение →429 generation_busy.

Одинаковый Idempotency-Key и параметры →202 тот же id и текущее состояние, без нового вызова Qwen, включая конкурентный повтор. Другие параметры →409 idempotency_conflict. Отсутствие key создаёт новую операцию при каждом POST. Порядок focus_areas несущественен; порядок разделов существенен. Старый ключ после истечения/отмены →410 preview_expired, без нового теста. Для явного повторного запуска используйте новый ключ.

Готовый preview переживает перезапуск до истечения срока. queued/generating при старте переходят в error/processing_interrupted, без автоматического повторного вызова; явный повтор требует нового ключа. Сбой после commit и до callback покрывается также общим сроком задания:30 минут от принятия, включая ожидание GPU; после него ошибка llm_timeout. Текущий начатый HTTP-вызов модели ограничен существующим серверным timeout, его процесс принудительно не завершается. Незавершённая генерация никогда не публикует результат после отмены/истечения.

`DELETE /template-previews/{id}?confirm=true` →204; повтор 204, неизвестный/чужой 404. Без confirm=true →422 confirmation_required. Отмена очищает технические payloads и запрещает позднюю публикацию. GET известного отменённого/истёкшего preview →410 preview_expired; неизвестного/чужого →404 not_found. Flutter сохраняет локальный черновик при любой неопределённости.

### Проверка контекста и длинная обработка

Для preview и кандидатов проверяется фактическое context_length настроенной модели через Ollama/api/ps. При необходимости прогревается только уже установленный тег. Словарь и merges токенизатора берутся из `/api/show` установленной модели; для qwen35 подсчёт проверяется на синтетических raw-запросах этой же Ollama. Никакие веса и другие модели не скачиваются. Для неподдержанного токенизатора остаётся консервативная байтовая оценка; она может дать отказ, но не разрешает скрытое усечение.

Бюджет включает system prompt, inline/snapshot шаблона, инструкции, JSON-схему, исходный текст, запас 1024 токена на chat-обвязку и 12288 токенов на итоговый ответ. Если полный вход помещается, используется direct — один итоговый запрос. Иначе hierarchical: **каждая** часть исходного текста проходит извлечение конкретных фактов в исходном порядке; затем все факты объединяются и, при необходимости, сжимаются по группам, после чего применяется выбранный шаблон. Разбиение не пропускает символы; простое взятие начала/конца или top-N фактов не используется. Поздние уточнения должны сохранять связь с заменяемыми значениями.

Внутренние map/reduce явно используют think=false, temperature0.2 и num_predict8192; итоговый запрос новых preview/кандидатов явно использует think=false, прежнюю temperature0.2 и серверный предел ответа 12288 токенов. num_ctx, размер окна и параметры GPU не меняются. Незавершённый/обрезанный ответ не сохраняется как ready. Если шаблон сам не помещается, сжатие перестало уменьшать объём, превышено 12 раундов объединения или 30 минут на всё задание, результатом будет документированная ошибка. Проверка структуры и вместимости не является математической гарантией фактической полноты LLM; конкретные длинные примеры проверяются отдельно.

### Markdown, оглавление и старые summary

Ответы списка/GET/PATCH/PUT summary дополнены:

```json
{
  "template_snapshot": null,
  "generation_options": null,
  "version": "79d40b54f1fb56bf40ed2431d1329dc1dccf86244443a40aec04b33115db5eb38",
  "navigation": [
    {"id":"ym-h-0","title":"Общая информация","level":2,"heading_index":0,"line_index":0},
    {"id":"ym-h-1","title":"Содержание","level":2,"heading_index":1,"line_index":4}
  ]
}
```

Здесь показаны только новые поля; остальные поля SummaryOut сохраняются. Для новых результатов template_snapshot — полный неизменяемый Template на момент принятия, для старых результатов — null. Ручное редактирование content не меняет снимок происхождения. Старые content не переписываются; новые служебные поля совместимы с прежними клиентами.

`navigation` вычисляется сервером по текущему content, включая после ручного редактирования. Заголовки ATX (`#`–`######`) вне fenced code blocks получают ASCII ID `ym-h-N`, где N = `heading_index` с нуля; `line_index` — строка Markdown с нуля. Одинаковые и кириллические названия получают разные ID по порядку. Для старого произвольного Markdown без таких заголовков navigation может быть пустой. После изменения content индексы могут измениться — Flutter обновляет навигацию вместе с документом.

В генерируемом документе верхние разделы имеют `##`, темы repeated — `###`, их подразделы — `####`. Для системного default раздел «Содержание» backend заполняет ссылками `#ym-h-N` к тематическим заголовкам. **HTML-якорей в content нет.** Flutter должен назначить ключи виджетам заголовков по порядковому heading_index и перехватывать ссылки `#ym-h-N`; стандартные GitHub-якоря не предполагаются. Поле navigation также позволяет построить собственное оглавление для любого шаблона. ID устойчивы при неизменном content и не зависят от транслитерации/повторов названия.

Цвета задаёт Flutter. Backend хранит чистый Markdown, `**жирное выделение**` — семантическое, без встроенных цветов.


## Выбор кандидата summary без изменения сохранённой встречи

Для экранов сравнения/переключения шаблонов Flutter использует **summary-selections**. Первое сохранение через этот сценарий тоже выполняется только на «Готово». Прежние `/transcripts/process`, `/transcripts/{id}/process` и audio/confirm остаются совместимыми: они по-прежнему сразу создают summary после успешной генерации. Для выбора вариантов не вызывайте их и не создавайте копии встречи.

### 1. Открыть сессию

`POST /summary-selections`, **обязателен Idempotency-Key**1–128 символов. Для сохранённой встречи:

```json
{"summary_id":"ae9f4066-891e-43ec-8485-fdd081218cf2"}
```

Для первой текстовой встречи:

```json
{"text":"Полный исходный транскрипт...","title":"Совещание команды","folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}
```

Для ранее сохранённого текстового источника без summary:

```json
{"transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091","title":"Совещание команды","folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"]}
```

Для аудио после ASR/проверки:

```json
{
  "audio_session_id":"ac70db65-b32d-4dbb-925a-e0b2a91aad4a",
  "title":"Аудиовстреча","folder_ids":["60f04cf2-6047-4405-a008-a63544d4f357"],
  "confirm":true,
  "reviewed_text_sha256":"047c3c26db38f4b1b8d2fdbf593ab7414c177a170daef7e9d54d3514bd07c9af",
  "boundaries_reviewed":true
}
```

Ровно один из text/transcript_id/summary_id/audio_session_id. Для новой встречи обязательны название 1–200 символов и 1–100 различных существующих папок; для summary_id title/folder_ids не передаются — сохраняются текущие название и связи. Ограничения длинного текста совпадают с preview; неизвестные поля запрещены. Для audio_session_id требуется ready_for_review, confirm=true, актуальный SHA и подтверждение границ при предупреждениях, как в прежнем confirm. Второй ASR не выполняется. Обход проверки аудио через transcript_id запрещён. Для уже сохранённой аудиовстречи используйте summary_id.

201 при создании,200 при повторе; ответ Selection:

```json
{
  "id":"76865b3c-3234-4c79-a9d9-eb7b12af8e31",
  "status":"open",
  "transcript_id":"d2a4aee4-9ffb-4daa-bcd8-6b0bfc7a0091",
  "summary_id":null,
  "summary_version":null,
  "accepted_candidate_id":null,
  "expires_at":"2026-10-24T20:00:00Z",
  "candidates":[]
}
```

Для существующего summary_id summary_version содержит непрозрачную 64 символьную версию, необходимую для принятия. Сохраняйте её из ответа, не вычисляйте на клиенте. POST сохраняет источник/снимок одной короткой транзакцией; генерацию сам не запускает. Для нового текста создаётся ровно один Transcript; Summary до принятия отсутствует и в список истории не попадает. Для готового источника/аудио новый Transcript не создаётся.

`GET /summary-selections/{id}` →200 Selection, включая текущие candidates. Каждый элемент имеет форму Candidate ниже. Этот GET ничего не генерирует. Статусы сессии open/accepted/cancelled/expired. Срок открытой сессии 24 часа, одновременно до 10 открытых сессий встреч на пользователя. Для нового источника одновременно допускается одна открытая сессия; для сохранённого summary несколько сессий защищены проверкой версии.

### 2. Создать/получить кандидата

`POST /summary-selections/{id}/candidates`, **обязателен отдельный Idempotency-Key**1–128 символов:

```json
{
  "template_id":"019a0120-0000-7000-8000-000000000005",
  "detail_level":"normal","focus_areas":["tasks","deadlines"],
  "additional_instructions":"Сохрани технические названия."
}
```

Те же правила настроек и default template, что в обычной генерации. POST202 быстро возвращает Candidate; polling `GET /summary-candidates/{id}`200:

```json
{
  "id":"9eb86384-b41e-4727-9f72-cb78f33106c4",
  "selection_id":"76865b3c-3234-4c79-a9d9-eb7b12af8e31",
  "status":"queued","content":null,"template_snapshot":{},
  "generation_options":{"detail_level":"normal","focus_areas":["deadlines","tasks"],"additional_instructions":"Сохрани технические названия.","template_id":"019a0120-0000-7000-8000-000000000005"},
  "navigation":[],"processing_metadata":{},"error":null,
  "created_at":"2026-10-23T20:00:00Z","expires_at":"2026-10-24T20:00:00Z"
}
```

`template_snapshot` в сокращённом примере показан `{}`; фактически это **полный** неизменяемый Template на момент принятия кандидата. Сохраняются и все параметры генерации. Изменение/удаление шаблона не изменяет готового кандидата. Исходный проверенный текст заморожен сессией; повторного ASR и копий встречи/папок нет.

Статусы кандидата queued/generating/ready/error; после очистки в Selection.candidates могут быть discarded/expired без payload. При ready заполнены Markdown/navigation. Ошибки и длинная обработка совпадают с preview. Общий срок задания 30 минут от принятия, включая GPU-очередь. Максимум 2 queued/generating на пользователя совместно с preview; максимум 12 запусков в одной сессии, включая ошибки.

**A→B→A:** при одинаковом снимке шаблона и параметрах уже готовый/выполняющийся кандидат в этой сессии возвращается повторно даже с новым ключом; новый Qwen не запускается. Все ключи сохраняются как алиасы операции. Если шаблон в каталоге изменён, его новый снимок создаёт новый вариант. Назад/вперёд используйте существующие candidate_id и GET; POST для навигации не требуется.

После error тот же ключ возвращает прежнюю ошибку, не запускает модель. Явный повтор с новым ключом создаёт новую попытку. Готовые варианты продолжают храниться до принятия/отмены/истечения. Одинаковый ключ с другими исходными параметрами →409 idempotency_conflict. Идентичность ключа сравнивает template_id, параметры и источник сессии, а не позднейшую версию каталога.

При перезапуске ready сохраняется, queued/generating становится error/processing_interrupted. Сбой между commit и callback не теряет операцию: при следующем старте либо после общего срока она становится ошибкой. Автоматического повторного Qwen нет. Конкурентные запросы с одним ключом сериализуются PostgreSQL.

### 3. «Готово»: принять один вариант

`POST /summary-selections/{id}/accept`:

```json
{
  "candidate_id":"9eb86384-b41e-4727-9f72-cb78f33106c4",
  "expected_version":"79d40b54f1fb56bf40ed2431d1329dc1dccf86244443a40aec04b33115db5eb38"
}
```

Для первого summary expected_version отсутствует или null; для существующего обязателен полученный summary_version. Принимается только ready-кандидат этой сессии.200 SummaryOut: атомарно сохраняются ровно выбранные content/template_snapshot/generation_options; navigation вычисляется из принятого content. Существующие summary.id, transcript_id, title и **текущие** привязки к папкам сохраняются. Для первой встречи Summary создаётся только сейчас; аудиосессия становится completed без нового ASR.

Версия SummaryOut.version меняется при ручном PATCH и принятии кандидата. Перенос по папкам не меняет версию содержимого и не блокирует принятие: текущие связи сохраняются. Даже ручное изменение A→B→A увеличивает внутреннюю ревизию. Если документ изменён после открытия сессии →409 summary_version_conflict, без перезаписи. Перечитайте текущий summary и откройте новую сессию; нельзя просто подставить новую версию в старую сессию. Внешнее изменение источника →409 source_conflict.

Повтор accept с тем же candidate_id →200 **сохранённый ответ первого принятия**, без новой записи/Qwen и без затирания поздней ручной правки. Если позднее summary редактировали, актуальный документ читается отдельным GET/summaries/{id}; квитанция accept остаётся снимком подтверждённой операции. Другая candidate_id после принятия →409 selection_closed.

Выбранный кандидат и квитанция сохраняются вместе с обычной встречей. Не выбранные результаты/инструкции и техническая копия источника очищаются в той же транзакции. При удалении самого summary все связанные технические копии тоже очищаются; остаются только IDs/ключи/хеши для безопасного отказа старым повторам. Старый POST создания сессии не воскрешает удалённую встречу.

### 4. Отмена и истечение

`DELETE /summary-selections/{id}?confirm=true` →204, повтор 204. Без явного подтверждения 422 confirmation_required; неизвестная/чужая сессия 404. Принятую сессию отменять этим endpoint нельзя 409 selection_closed: сохранённая встреча удаляется только прежним API summary.

Отмена не меняет сохранённый summary. Не выбранные candidates, инструкции, технический исходный текст и прогресс очищаются; поздний worker не может вернуть результат. Собственный временный Transcript первой текстовой сессии удаляется, если не используется другими данными. Заимствованный/аудиоисточник остаётся. При истечении 24 часов выполняется такая же очистка, статус expired; фоновая очистка раз 60 секунд, обращение проверяет срок сразу. Завершённые ключи не освобождаются для повторного создания операции.

GET известной закрытой Selection →200 cancelled/expired; GET очищенного Candidate →410 candidate_expired. Повтор POST создания сессии по её старому ключу после отмены/истечения/удаления встречи →410 selection_closed. Новый candidate-запрос после принятия 409, после отмены/истечения 410. Старый ключ уже очищенного кандидата 410. Принятая квитанция не истекает по expires_at открытой сессии; хранится до удаления обычной встречи.

До принятия исходник временно блокируется открытой сессией (`GET transcript.is_locked=true`; PATCH/другая генерация 409 selection_in_progress). Успешный непринятый кандидат не является первой успешной обработкой встречи: после отмены/истечения источник без ранее сохранённого summary снова можно редактировать или удалить через подходящий прежний API. После accept постоянная блокировка действует как раньше. Сохранённые ранее источники не разблокируются при отмене выбора.

При сетевой ошибке Flutter сохраняет локальный черновик и сначала читает известные session_id/candidate_id либо повторяет **тот же** ключ. Не удаляйте исходный summary и не создавайте новую встречу, чтобы проверить неопределённый результат accept.
