## Реализация

В профиле приложения доступен экран «Подключение»: USB, удалённый HTTPS, адрес сервера, скрытый ввод/вставка/показ ключа, проверка и применение. Профиль и адрес сохраняются; ключ хранится отдельно в защищённом хранилище устройства для каждого origin. При смене origin поле очищается. Ключ не входит в настройки JSON, контекст фоновой записи, журнал аудио, код, assets или параметры сборки.

USB: `http://127.0.0.1:8000/api/v1`, требуется `adb reverse tcp:8000 tcp:8000`. HTTPS: `https://194.117.80.169/api/v1`; проверка TLS включена. LAN в этом deployment не используется. Применение выполняет `/health` в корне и `/api/v1/auth/me`, проверяет demo-аккаунт, затем переключает приложение без пересборки. Неуспешная проверка не заменяет действующий доступ.

Общая политика запросов охватывает обычный API, polling, каталог и тесты шаблонов, выбор вариантов, аудио в UI и foreground service. Она задаёт ровно один `X-Demo-Key`, запрещает передачу ключа другому origin и не следует перенаправлениям. JSON — 20 секунд, бинарный upload — 360 секунд, подключение — 20 секунд. Аудио остаётся бинарным WAV/PCM16 из существующего непрерывного recorder: переход на AAC без изменения механизма восстановления не выполнялся. Новые записи используют фрагменты 30 секунд (не выше лимита сервера), жёсткий предел 60 секунд; старые журналы сохраняют прежние границы.

Повторы сохраняют ключи идемпотентности, session/sequence, границы, SHA256 и байты. Интервалы временных ошибок — 2/4/8/16/30 секунд, учитывается Retry-After. 401/403 требуют исправить доступ; 409/422 не запускают бесконечные повторы. HTML-ответы шлюза 502/503/504 обрабатываются как временная ошибка. Локальный фрагмент удаляется только после проверенного и сохранённого ACK.

Данные разделены по хэшу origin + access_mode + подтверждённый account ID. Старые персональные файлы не мигрируют в demo и автоматически не отправляются. Фоновая запись закреплена за своим подключением и каталогом. Смена сервера во время записи/отправки блокируется с пояснением; продление ключа того же аккаунта и origin доступно без переназначения операции. Незавершённые операции остаются в исходном разделе данных.

Пройден полный сценарий на мобильной сети:

## Ввод ключа на Windows

Ключ вводится пользователем непосредственно в приложении. Приватный файл создаётся backend-окружением в `%LOCALAPPDATA%/YourMettings/demo-access-key.txt`. Для установленного из Store Codex Windows может перенаправлять его в `C:/Users/Алексей/AppData/Local/Packages/OpenAI.Codex_2p2nqsd0c76g0/LocalCache/Local/YourMettings/demo-access-key.txt`. Расположение проверялось только по метаданным, без чтения содержимого. Ключ нельзя публиковать в чате, Git или отчётах.

Защищённое хранение: [flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage), версия 11.1.0. Ошибка хранилища не приводит к переходу на обычный файл.
