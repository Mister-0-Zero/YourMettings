# Проверка шаблонов на локальной Qwen

Дата: 23 октября 2026 года. Модель из рабочей конфигурации: `qwen3.8:27b`. Использован универсальный шаблон, `detail_level=normal`, temperature=0.2. Контекст и остальные параметры модели не изменялись. Фактически загруженная Ollama модель сообщала окно 32768 токенов.

Данные синтетические: это проверка сохранения тем, условий, задач и заключительных уточнений, без чтения пользовательских встреч. Обычные записи transcript/summary/folder/audio не создавались. Во время вызова использовалась существующая блокировка GPU без открытой транзакции PostgreSQL.

| Проверка | Исходный текст | Тем | Время | Входных / выходных токенов |
|---|---:|---:|---:|---:|
| Несколько самостоятельных тем | 1409 символов | 4 | 48,91 с | 2438 / 4333 |
| Длинная встреча с повторными обсуждениями | 22689 символов | 5 | 63,94 с | 8046 / 5610 |

Оба ответа завершены с `done_reason=stop`. Четыре верхних раздела соответствуют шаблону и идут в заданном порядке. Контрольные сведения обнаружены в обоих результатах. Дополнительно просмотрено содержание: заключительная тема «Вектор-93», бюджет 475000 рублей, задача Ирины к 12 ноября и перенос выпуска API с 30 октября на 3 ноября сохранились; повторные раунды обсуждения объединены по темам. Лимит 200 запросов остался открытым вариантом, согласованный лимит — 120.

Проверен длинный текст из 22689 символов, а не весь допустимый HTTP-лимит 100000. Лимит сохранения текста не равен вместимости окна контекста: очень длинный текст вместе со сложным шаблоном и ответом может превысить окно модели. Эта версия не добавляет иерархическое разбиение длинного текста и не меняет контекст Ollama.

Это проверка указанных примеров, а не доказательство фактической точности любого будущего ответа LLM. Результат по-прежнему проверяет пользователь. Реальная генерация проверена на normal; brief/detailed и flexible дополнительно проверены автоматическими тестами промпта/структуры.

Воспроизведение из `backend`:

```powershell
.\.venv\Scripts\python.exe tests/e2e_templates_real.py
```

Скрипт использует установленную модель и существующую конфигурацию; ничего не скачивает. Перегенерирует только перечисленные диагностические файлы. Время и формулировки могут отличаться; отсутствие контрольных фактов завершает проверку ошибкой.

Миграции проверялись на отдельной тестовой PostgreSQL, включая откат/обновление и сохранность прежних данных. Рабочие службы автоматически не перезапускались. Для включения нового API нужно применить `alembic upgrade head` из backend и перезапустить один backend-процесс. ASR-worker не изменён и не требует обновления.
