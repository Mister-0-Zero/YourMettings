# Flutter: длинные тесты и выбор итогового summary

Реализован запрос из mobile/docs/BACKEND_TEMPLATE_VARIANTS_REQUEST.md. Точные схемы и ошибки — в [API_CONTRACT.md](API_CONTRACT.md). Реализация/API — **b6254ae**, ветка backend; сервер уже работает на этом коде с миграцией 0008. Последующий commit с результатами проверки не меняет API. Не редактируйте backend из mobile-worktree.

## Тест шаблона

1. `GET /api/v1/template-preview-examples` — три названия, IDs, количество слов/символов/байтов.
2. `GET /api/v1/template-preview-examples/{id}` — полный text. IDs: team-standup, work-report, engagement-ideas. Размеры: 5703/5908/5953 слова. Примеры синтетические и не попадают в историю.
3. `POST /api/v1/template-previews` с полным text и текущим inline template; передавайте Idempotency-Key. Новый лимит: 15000 слов, 200000 символов, 400000 UTF-8 байт одновременно. Уберите старое ограничение 12000; текст не обрезать.
4. Ответ 202 содержит id/expires_at; polling `GET /api/v1/template-previews/{id}`. Статусы queued/generating/ready/error, поля content/navigation/error/processing_metadata.
5. TTL1 час. Готовый тест переживает перезапуск; незавершённый становится error/processing_interrupted и не запускается повторно автоматически. Та же операция с тем же ключом возвращает тот же id/состояние. Для явного повтора после ошибки — новый ключ.
6. Истёкший/отменённый тест →410, неизвестный/чужой 404. `DELETE /template-previews/{id}?confirm=true` отменяет с очисткой payload; повтор 204. Локальный черновик не очищать при сетевой ошибке.

## Сравнение кандидатов встречи

**Новый экран выбора использует selection API.** Старые endpoints /transcripts/process и audio/confirm остаются однократным сценарием с немедленным сохранением результата; не вызывайте их для генерации кандидатов.

Открыть `POST /api/v1/summary-selections` с обязательным новым Idempotency-Key:

- Сохранённая встреча: `{"summary_id":"UUID"}`. Название и папки не передаются.
- Новый текст: `{"text":"весь текст","title":"Название","folder_ids":["UUID"]}`.
- Проверенный аудиоисточник: `{"audio_session_id":"UUID","title":"Название","folder_ids":["UUID"],"confirm":true,"reviewed_text_sha256":"SHA256","boundaries_reviewed":true}`. Проверка границ обязательна только при предупреждениях. Повторного ASR нет.
- Сохранённый текстовый источник без summary: transcript_id вместо text. Для аудио этот путь не заменяет подтверждение проверки.

201 при создании,200 при идемпотентном повторе. Сохраните session.id, transcript_id, summary_id, **summary_version** и expires_at. Сессия не генерирует Qwen и не создаёт summary. Для первой текстовой встречи сохраняется один исходный Transcript, история остаётся пустой до «Готово».

Создать вариант: `POST /api/v1/summary-selections/{id}/candidates` с отдельным обязательным Idempotency-Key и настройками `{template_id, detail_level, focus_areas, additional_instructions}`. Поля настроек необязательны с прежними default.202 возвращает стабильный candidate.id. Polling/чтение: `GET /api/v1/summary-candidates/{id}`. Он возвращает content/navigation, полный template_snapshot, generation_options, processing_metadata, error и срок.

**Назад/вперёд:** храните список candidate_id и переключайтесь между готовыми вариантами через локальный кэш/GET. Новая генерация для перехода не нужна. Повтор A→B→A с тем же снимком/настройками также найдёт готовый A без нового Qwen. После изменения шаблона его новый снимок считается новым вариантом. После error старый ключ не запускает повтор, новый ключ создаёт явную новую попытку.

Состояние всей сессии: `GET /api/v1/summary-selections/{id}` — open/accepted/cancelled/expired и список кандидатов. До принятия оригинальный summary не меняется.

## «Готово»

`POST /api/v1/summary-selections/{id}/accept`:

```json
{"candidate_id":"UUID","expected_version":"полученный summary_version"}
```

Для первой встречи expected_version отсутствует/null. Для существующей передавайте исходный summary_version. Ответ 200 — выбранный SummaryOut: content/template_snapshot/generation_options/navigation согласованы, прежний summary.id и transcript_id сохранены. Название и текущие папки существующей встречи сохраняются. Перемещение папок не блокирует принятие; ручной PATCH содержимого/названия, включая A→B→A, приводит к 409 summary_version_conflict. Не подставляйте новую версию в старую сессию: перечитайте документ и откройте новую.

Повтор того же accept возвращает точно сохранённую квитанцию первого принятия, без повторной записи. Если документ позже редактировали, его текущее состояние получают GET/summaries/{id}. После потерянного ответа сначала GET сессии или повтор accept того же candidate_id; не удаляйте встречу и не создавайте её заново.

## Отмена, сроки и очереди

`DELETE /api/v1/summary-selections/{id}?confirm=true` →204, повтор 204. Это отмена выбора, **не удаление исходного summary**. Принятую сессию отменить нельзя 409. Не выбранные технические данные очищаются; поздний worker не возвращает их. Свой новый временный Transcript удаляется, если не используется, заимствованный/аудиоисточник сохраняется. Отмена непринятой новой встречи снова разрешает редактировать источник; сохранённые ранее источники остаются неизменяемыми.

Открытая сессия 24 часа, максимум 10; кандидатов до 12 запусков на сессию. До 2 генераций queued/generating совместно с preview; занятая очередь 429 generation_busy. Общий срок задания 30 минут с ожиданием GPU. Прерванные при старте задания получают processing_interrupted, готовые сохраняются. Технические payloads истекают/очищаются, старые ключи остаются закрытыми и не создают дубликаты.

GET закрытой известной сессии возвращает 200 со статусом; GET очищенного кандидата 410. Старый POST создания по закрытому ключу 410. Результат принятой операции хранится до удаления обычной встречи; её удаление очищает технические копии и оставляет ключи закрытыми. При любой сетевой неопределённости сохраняйте локальные ключи/IDs/черновик до выяснения состояния.

Во время открытой сессии transcript.is_locked=true. PATCH источника или прежний запуск обработки этого источника даст 409 selection_in_progress. Не обходите блокировку созданием дублирующей встречи.

## Отображение и сервер

Навигация прежняя: heading_index/line_index и ASCII ID ym-h-N; обработчик Markdown-ссылок должен переходить по этим IDs, не по GitHub-якорям. После принятия/редактирования обновляйте content вместе с navigation. version — непрозрачная версия содержимого; updated_at её не заменяет.

Параметры GPU/контекста не менялись. Вместимость проверяется по фактической модели и её проверенному токенизатору; при необходимости обрабатываются все части без обрезки. context_limit_exceeded означает явный отказ, частичный Markdown как ready не возвращается. В processing_metadata можно показать этап и число обработанных частей; не фиксируйте в клиенте полный набор служебных полей.

Для других установок backend нужны зависимость tokenizers, миграция 0008 и перезапуск одного процесса. В текущей рабочей установке это уже выполнено; ASR-worker менять не требуется. Адреса и USB-подключение — в [FLUTTER_HANDOFF.md](FLUTTER_HANDOFF.md). [Отчёт проверки](VARIANTS_E2E_RESULT.md): 275 тестов, три встроенных примера, нагрузочный вход 11406 слов и три полных asset-файла самого Flutter. Примеры приложения можно использовать напрямую: не требуется заменять их примерами серверного каталога. Их SHA-256 сверены; все три обработаны без обрезки. LAN-запрос в момент проверки дал таймаут, loopback работает; USB reverse уже настроен, UI телефона не проверялся.
