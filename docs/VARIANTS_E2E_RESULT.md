# Проверка длинных входов и выбора варианта summary

Дата проверки: 23–24 октября 2026. Реализация/API: `b6254ae`, ветка `backend`.

## Автоматические проверки

`backend/.venv/Scripts/python.exe -m pytest -q --tb=short` из `backend`: **275 passed**, 53,25 с. Единственное предупреждение — прежнее предупреждение Starlette об httpx.

Покрыты PostgreSQL-персистентность, идемпотентные повторы и конкурентные запросы, A→B→A без повторной генерации, отсутствие обычного summary до принятия, атомарное принятие с сохранением ID/текущих папок, конфликт с ручной правкой (включая A→B→A), повтор accept после потери ответа, отмена/TTL, поздние результаты, перезапуск и потерянный callback. Аудиоисточник переиспользуется без ASR; ранее действовавшие аудио/summary/delete API входят в полный прогон.

## Реальный Qwen

Использован настроенный `qwen3.8:27b`, GGUF qwen35 Q4_K_M, фактически загруженное окно **32768**. Модель/контекст/GPU и `.env` не изменялись. Проверенный локальный токенизатор восстановлен из метаданных установленной GGUF; две контрольные строки совпали с Ollama: 63=63 и 70=70 токенов. Внешние веса/токенизаторы не скачивались.

Новые preview/candidate запросы используют `think=false`, temperature 0.2; итог ограничен 12288 выходными токенами, промежуточное извлечение фактов — 8192. Во всех четырёх случаях full_source_used=true, missing_markers=[], runtime_budgets_fit=true; вызовы завершены stop. Контрольные факты из начала/середины/конца сохранились. При ручном чтении в отчёте встретилась историческая задача о назначении подписанта рядом с уже уточнённым назначением в итогах. Общее правило поздних уточнений усилено; итоговый прогон опубликован целиком для проверки качества пользователем. Автоматической гарантии полной смысловой согласованности нет.

## Воспроизведение

Из `backend`, при доступном настроенном Ollama и PostgreSQL:

```powershell
.venv\Scripts\python.exe tests/e2e_variants_real.py
.venv\Scripts\python.exe tests/e2e_variants_real.py --mobile-examples D:\programming\VSCode\project\YourMettings-mobile\mobile\assets\meeting_examples
```

Тест использует общий GPU-lock, полный исходный текст и синтетические данные; не создаёт пользовательские Transcript/Summary/AudioSession. Время зависит от загрузки GPU и размера ответа. Выходные Markdown и validation.json перезаписываются намеренно. Обычный pytest не вызывает реальную модель.

## Развёртывание

Миграция `0008_summary_variants` применена к рабочей базе, `alembic check` не обнаруживает расхождений. Для других установок нужны обновление зависимостей, `alembic upgrade head` и перезапуск одного backend; ASR-worker менять не требуется.

Рабочий backend перезапущен на коде b6254ae (PID 43000, один процесс Uvicorn). ASR-worker PID 41736 оставлен работающим. `start-dev.ps1 -CheckOnly` проверил все четыре компонента успешно. Live HTTP проверка нового preview с реальным Qwen завершилась ready; повтор POST вернул тот же ID; DELETE/повтор DELETE — 204/204, GET и старый POST после очистки — 410. Число обычных transcripts/summaries/folders/audio_sessions до и после совпало. OpenAPI содержит новые маршруты; чтение папок/summary/шаблонов и loopback /health — 200.

Сервер слушает 127.0.0.1 и 192.168.1.100:8000, но прямой запрос к LAN-адресу в момент проверки получил ConnectTimeout. Причина не установлена; известная проблема VPN ранее оставлена вне задачи. Firewall/VPN/маршруты не менялись. Подключённый Android авторизован в ADB, reverse tcp:8000→tcp:8000 уже существует; проверка UI приложения не проводилась. Для разработки на ПК доступен http://127.0.0.1:8000/api/v1; на USB-телефоне используется тот же адрес с reverse.
