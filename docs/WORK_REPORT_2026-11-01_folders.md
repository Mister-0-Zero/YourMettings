## Что реализовано

Существующий `PUT /api/v1/summaries/{id}/folders` получил отдельную входную схему SummaryFolderAssignment с optional expected_folder_ids. Общая FolderAssignment, от которой зависят создание/обработка, не расширялась. Целевые папки — по-прежнему 1–100 различных доступных UUID; expected — 0–100, явный null запрещён. OpenAPI отражает optional array и отсутствие null.

Под существующими user/row locks проверяются summary/целевые папки и текущий набор. Уже достигнутый target возвращает 200 без мутации даже со старым expected. При другом текущем наборе и несовпавшем expected возвращается 409 summary_folders_conflict без потери параллельного изменения. Без expected сохраняется совместимость с прежним полным заменением связей. Ответ строится до освобождения locks, исключая смешанный снимок.

Добавление в B из A,C передаёт A,B,C; перемещение из A в B — B,C. Это один Summary/Transcript, без копирования. Title/content/version и снимок шаблона не меняются; реальное изменение размещений обновляет updated_at, no-op не обновляет. Принятие варианта сохраняет актуальные размещения. Это CAS набора, а не durable receipt/ревизия истории A→B→A; ограничение явно описано.

Обновлены [API_CONTRACT.md](API_CONTRACT.md), [openapi.json](openapi.json), [FLUTTER_HANDOFF.md](FLUTTER_HANDOFF.md); создан [FLUTTER_FOLDERS_HANDOFF.md](FLUTTER_FOLDERS_HANDOFF.md) с точными запросами, ошибками и правилами восстановления клиента. Ошибки: 409 summary_folders_conflict; 404 для недоступного summary/целевой папки; 422 validation_error для входа. Авторизация остаётся прежней.

Новый `tests/test_summary_folders.py` содержит 20 сценариев с параметризацией:

- move с сохранением другой папки и единственного документа/источника, единое редактирование из разных размещений;
- add, одинаковый повтор после потерянного ответа, независимость от порядка, no-op с неизменным updated_at;
- конфликт устаревшего expected, legacy PUT без expected;
- конкурентные одинаковые и разные target, 200/200 и 200/409 соответственно;
- rollback после сбоя формирования ответа до commit;
- чужие/несуществующие summary и целевые папки, null/дубликаты/UUID/лимиты/пустой target;
- expected [] для существующего legacy-документа без связей, при сохранённом запрете target [];
- отсутствие нового поля в text/audio creation/confirm schemas;
- последовательная и конкурентная гонка удаления исходной папки с move при другом сохранившемся размещении;
- конкурентное принятие варианта и move без дубликата или восстановления прежних папок.

В первом полном прогоне было 414 passed/1 failed: существующая проверка audio OpenAPI обращалась к FolderAssignment, которая больше не является самостоятельной endpoint-схемой. Проверка исправлена на фактически используемую SummaryFolderAssignment без ослабления требования minItems=1; после этого весь suite прошёл. Первые целевые проверки до двух финальных delete-сценариев: 62 passed. Единственный итоговый warning — существующий Starlette/httpx deprecation, зависимости не менялись.

OpenAPI экспортирован из app.openapi() без lifespan, listener, запуска worker, вызова ASR/Qwen или изменения БД. Выполнены git diff --check, проверка локальных Markdown-ссылок изменённых документов, структурное сравнение экспорта с фактическим app.openapi и проверка отсутствия локальных секретов в изменениях.
