## Почему Alembic удалось выполнить, а backend пока нельзя запустить

В приватной конфигурации включён **DEMO_ENABLED=true** со сроком **29 октября 2026, 16:46 МСК**. К 31 октября он истёк. Приложение валидирует срок уже при загрузке Settings, до старта HTTP; это же мешает обычному импорту Alembic environment.

Координатор отдельно разрешил **только локальные дочерние процессы Alembic** с process-only `DEMO_ENABLED=false` для выполнения уже согласованной миграции. Использован отдельный словарь окружения subprocess: родительская среда и .env не менялись, сервер в этом окружении не запускался, никакой listener не открывался. После завершения дочерних процессов override прекратился вместе с ними.

Это не режим работы сервиса, не обход мобильной авторизации и не успешная HTTP-проверка. Обычная конфигурация по-прежнему корректно отказывает в запуске с истёкшим доступом. Для продолжения требуется **явное решение владельца о сроке продления текущего demo-доступа либо другом согласованном режиме**; ключ не заменять/не продлевать без такого решения.

3. Подтвердить runtime нового кода и 0010, health и auth-me с действующим доступом, защищённость анонимных запросов и новые поля live OpenAPI.
