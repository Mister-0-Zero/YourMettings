## Почему обычный публичный запуск заблокирован, а миграция выполнена отдельно

В приватной конфигурации включён **DEMO_ENABLED=true** со сроком **29 октября 2026, 16:46 МСК**. К 31 октября он истёк. Приложение валидирует срок уже при загрузке Settings, до старта HTTP; это же мешает обычному импорту Alembic environment.

Координатор отдельно разрешил **только локальные дочерние процессы Alembic** с process-only `DEMO_ENABLED=false` для выполнения уже согласованной миграции. Использован отдельный словарь окружения subprocess: родительская среда и .env не менялись, сервер в этом окружении не запускался, никакой listener не открывался. После завершения дочерних процессов override прекратился вместе с ними.

Это не режим работы сервиса, не обход мобильной авторизации и не успешная HTTP-проверка. Обычная конфигурация по-прежнему корректно отказывает в запуске с истёкшим доступом. Для продолжения требуется **явное решение владельца о сроке продления текущего demo-доступа либо другом согласованном режиме**; ключ не заменять/не продлевать без такого решения.

## Как снова запустить USB-сеанс на этом ПК

Локальный операторский helper уже находится **вне Git**:

`C:\Users\Алексей\Documents\ChatGPT\YourMettings\start-summary-usb-session.py`

Из PowerShell выполнить:

```powershell
& 'D:\programming\VSCode\project\YourMettings\backend\.venv\Scripts\python.exe' 'C:\Users\Алексей\Documents\ChatGPT\YourMettings\start-summary-usb-session.py'
```

После перезагрузки при свободных 8000/8001 helper проверяет схему/зависимости и запускает только 127.0.0.1:8001 с прежним ключом и новым ограниченным двухчасовым process-only сроком. Ничего не скачивает и не исправляет .env. При занятом 8000 или непроверенном чужом 8001 отказывается запускать второй backend. При уже работающем собственном непросроченном USB-сеансе повтор переиспользует его, **не продлевая срок и не перезапуская процессы**; это проверено на текущем PID29420.

Если после 01:17 старый USB-процесс всё ещё слушает 8001, для нового локального сеанса:

```powershell
& 'D:\programming\VSCode\project\YourMettings\backend\.venv\Scripts\python.exe' 'C:\Users\Алексей\Documents\ChatGPT\YourMettings\start-summary-usb-session.py' --restart-expired
```

Этот флаг действует **только для истёкшего собственного USB-процесса**: проверяются локальная state-запись, listener, принадлежность проекту, PID/время создания и команда app.run --port8001. При активных LLM/ASR jobs helper отказывается завершать процесс: нужно дождаться их окончания. Неистёкший сеанс флаг не заменяет. Во время текущей приёмки ветка остановки истёкшего процесса намеренно не выполнялась; проверен только безопасный повтор живого сеанса.

State/срок/PID находятся в `%LOCALAPPDATA%\YourMettings\logs\usb-backend-session.json`, логи — в том же каталоге. Файл не содержит ключа. Helper привязан к этому Windows workspace и требует имеющихся окружений/ресурсов; это операторский запуск, не новый продуктовый способ авторизации и не автозапуск после входа.
